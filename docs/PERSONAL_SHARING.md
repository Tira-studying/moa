# 개인 명세서 관리와 통합 지출 공유

이제 모아는 **개인 원장은 각자 관리하고, 통합 지출 합계와 허용된 관리 정보를 함께 열람하는 구조**입니다. 소유자와 활성 공동관리자 1명이 각자 로그인합니다. Tailscale 장치 공유와 모아 계정 생성 방식은 기존과 같습니다.

## 1. 어디까지 공유하나요?

| 자료 | 본인 | 상대방 |
| --- | --- | --- |
| 명세서·미리보기·메일 첨부·파일명 | 확인·저장·삭제 | 접근 불가 |
| 일반 거래 목록·메모·영수증 사진 | 확인·수정 | 사용 내역 ‘함께 보기’에서 읽기 전용(거래 주인이 함께 보기를 끄거나 ‘상대에게 숨기기’한 거래는 제외) · 수정 불가 |
| 계좌 입출금·출금 확인·계좌 사용처·메모 | 확인·정리 | 접근 불가 |
| 분류 규칙·할부·중복 검토·고정 지출 | 관리 | 함께 열람 · 수정 불가 |
| 월별 청구액·납부 상태·기본 결제일 | 관리 | 함께 열람 · 수정 불가 |
| 개인 변경 이력 | 확인 | 접근 불가 |
| 통합 월별 총액·분야·카드사 합계 | 함께 확인 | 함께 확인 |
| 공동관리자 계정 추가·접근 해제·재설정 | 소유자만 관리 | 본인 암호 변경 가능 |

분류 규칙은 가맹점 공통 직접 분류를 공유합니다. 이번 거래만 지정한 분류와 메모는 공유하지 않습니다. 할부는 이름·원금·회차·완료 상태·예상 일정을, 고정 지출은 가맹점·금액·변동·반복 날짜·확인 상태를 함께 봅니다. 중복 검토는 해당 구성원의 전체 기간에서 찾은 후보의 날짜·가맹점·금액·건수와 제외 상태를 봅니다. **이 항목에 필요한 가맹점·날짜·금액은 열람 가능하지만, 원본 파일명·내부 거래 ID·메일은 공개하지 않습니다.** 거래 목록·메모는 2026-11-07부터 사용 내역 ‘함께 보기’(`shared_spending.py`)에서만 읽기 전용으로 공개합니다. 기본 켜짐이며 계정 · 설정에서 끄거나 거래 상세에서 거래별로 숨길 수 있습니다. 영수증 사진도 2026-11-09부터 같은 조건(보이는 거래만)으로 읽기 전용 공개합니다.

소유자 계정도 다른 사람의 거래 ID나 파일 ID로 개인 자료에 접근할 수 없습니다. 통합 화면은 브라우저에 원본 거래 목록을 받아 합치는 방식이 아니라 **서버가 집계한 합계만 받는 방식**입니다.

계좌 출금은 실제 지출로 직접 확인해 반영한 건만 통합 합계에 포함합니다. 이체·카드 대금·충전·보류한 카드 중복 후보는 포함하지 않습니다. 확인한 계좌 소비의 상세는 함께 열람의 중복·고정 지출에도 보내지 않고, 총액·분야·결제 수단 합계만 공유합니다.

**더보기 → 카드·계좌 연결**은 공동관리자·소유자 모두 본인 로그인 계정에만 연결합니다. API는 소유자 ID를 입력받지 않고 세션에서 결정합니다. 인증 작업은 동일 사용자이면서 시작한 로그인 세션에서만 조회·답변·취소하며, 소유자 역할도 상대의 작업을 읽을 수 없습니다. 인증 원문·연결 ID·추가 인증 연결 정보는 공동 열람이나 변경 이력으로 보내지 않습니다. 성공한 개인 연결과 원장·개인 버전·고정 문구 이력만 함께 저장합니다.

앱의 권한 분리이며 사용자별 DB 암호화는 아닙니다. 서버·백업 관리자는 DB와 비밀 파일에 접근할 수 있고, 소유자는 공동관리자 암호를 재설정할 권한이 있으므로 서버와 계정 관리자는 신뢰할 수 있는 사람이어야 합니다. NAS 관리자에게도 내용을 숨기는 종단 간 암호화 구조는 아닙니다.

## 2. 화면 사용

대시보드 위의 **내 지출 / 통합 지출**로 전환합니다.

- **내 지출**: 지금 로그인한 계정의 거래·소비 패턴·개인 납부 현황입니다.
- **통합 지출**: 조회 월을 골라 두 사람의 순사용액, 양수 사용액, 취소·환불, 분야별·카드사별 합계와 최근 6개월 추이를 봅니다. 상대방의 거래로 이동하는 버튼은 없습니다.
- **사용 내역·이메일·파일 추가·저장 기록**: 본인 자료만 관리합니다.
- **지출 관리 → 내 관리**: 본인 분류·할부·중복·고정 지출·청구·납부 기록을 관리합니다.
- **지출 관리 → 함께 열람**: 조회 월을 고르고 활성 구성원별 허용된 관리 정보를 읽습니다. 저장·수정·삭제·제외·복원 버튼은 없으며 실제 변경은 각자가 내 관리에서 처리합니다.
- **계정**: 본인 변경 이력과 공동 계정 관리 이력을 봅니다. 상대방의 개인 변경 이력은 보이지 않습니다.

통합 순사용액은 취소·환불을 차감하고, 분야·카드사 분포는 양수 사용액 기준입니다. 본인이 중복으로 제외한 거래는 개인·통합 집계에서 함께 빠집니다. 서로 다른 사람 사이의 같은 날·금액 거래는 자동으로 중복 취급하지 않습니다.

활성 계정의 자료만 통합합니다. 공동관리자의 접근을 해제하면 그 계정의 자료는 보관하지만 통합 합계에서 빠집니다. 접근을 다시 허용하면 다시 포함됩니다. 파일이 아직 등록되지 않았다면 통합 합계에도 반영되지 않으며, 실제 청구액이나 은행 잔액을 뜻하지 않습니다.

### 함께 열람 기능 업데이트

이미 개인 관리 버전을 적용했다면 이번 열람 기능 추가에는 새 DB 이전이나 자료 소유권 변경이 없습니다. 기존 절차로 코드를 받고 앱·메일 수집 이미지를 다시 빌드한 뒤 브라우저를 새로고침합니다. 아직 개인 관리 이전을 하지 않았다면 아래 백업·이전 절차부터 따릅니다.

## 3. 기존 자료를 어떻게 이전하나요?

이전 버전에는 금융 자료별 소유자 정보가 없었으므로, **기존 거래·명세서·분류·할부·납부 기록·메일은 모두 소유자(1번) 계정으로 보존**합니다. 카드사 이름이나 가맹점으로 실제 소유자를 추측하지 않습니다. 공동관리자의 개인 원장은 새로 시작합니다.

기존 자료에 상대방 명세서가 섞여 있다면 실제 원본을 가진 사람이 본인 계정으로 다시 등록하고, 소유자는 기존 복사본을 확인해 정리하세요. 두 계정에 같은 실물 명세서를 중복 등록하면 통합 합계에도 두 번 포함되므로, 파일의 실제 소유자가 관리하도록 맞춰야 합니다. 자동 재배정이나 계정 사이 원본 열람·이동 기능은 제공하지 않습니다.

이전 과정은 거래 ID와 파일 연결을 유지하며, 모두 성공한 경우에만 새 구조를 확정합니다. 오류가 발생하면 이전 변경 전체를 취소합니다. **업데이트 전 백업은 별도로 남기세요.** 새 구조 적용 시 기존 로그인 세션은 종료되므로 두 사람 모두 같은 아이디·비밀번호로 다시 로그인합니다.

### NAS에서 백업하고 업데이트

앱과 메일 수집만 멈춥니다. 접속 장치인 Tailscale은 실행 상태로 둡니다.

```sh
cd "$HOME/moa-projects/moa/deploy"
sudo docker compose -f compose.nas.yml --profile mail stop app mail-poller
sudo docker compose -f compose.nas.yml run --rm -T --no-deps --entrypoint python app -c '
import sqlite3
import os
from datetime import datetime, timezone
from pathlib import Path
os.umask(0o077)
source = sqlite3.connect("file:/data/cards.sqlite3?mode=ro", uri=True)
name = "/data/cards-before-personal-" + datetime.now(timezone.utc).strftime("%Y%m%d-%H%M%S") + ".sqlite3"
if Path(name).exists():
    raise SystemExit("같은 이름의 백업이 있습니다. 잠시 뒤 다시 실행하세요.")
target = sqlite3.connect(name)
source.backup(target)
target.close()
source.close()
print("DB 백업 완료:", name)
'
```

오류 없이 백업을 완료한 뒤 업데이트합니다. 백업은 기존 `moa_card-data` 볼륨 안에 유지됩니다.

```sh
cd "$HOME/moa-projects"
sudo docker run --rm -it \
  -v "$PWD":/git -w /git/moa \
  -v moa-git-ssh:/root/.ssh \
  alpine/git pull --ff-only origin main
cd moa/deploy
sudo docker compose -f compose.nas.yml --profile mail up -d --build app mail-poller
```

메일 수집을 사용하지 않는 설치는 `--profile mail`과 `mail-poller`를 제외합니다. 볼륨을 삭제하거나 계정을 초기화하지 않습니다. 이전 버전으로 되돌릴 때는 코드와 이전 DB를 함께 검토해야 하며 새 구조의 DB에 이전 코드를 바로 실행하지 않습니다. 운영을 재개한 뒤 새 자료를 추가했다면 그 자료도 별도로 보존해야 합니다.

### 이미 Mac으로 이전한 경우

Mac에서는 위 백업·중지 명령의 `sudo`를 빼고, 모든 Compose 명령에 `-f compose.mac.yml`을 추가합니다. 코드는 Mac의 기존 Git 인증으로 업데이트합니다.

```sh
cd "$HOME/moa-projects/moa"
git pull --ff-only origin main
cd deploy
docker compose -f compose.nas.yml -f compose.mac.yml --profile mail up -d --build app mail-poller
```

Docker 이미지에는 새 소유권 관리 모듈과 화면이 들어가므로 앱과 메일 수집 이미지를 함께 다시 빌드해야 합니다.

## 4. 개인 Gmail 연결

소유자(1번)는 기존 `.env`와 다음 파일을 그대로 사용합니다.

```text
secrets/
  gmail-app-password
  statement-password
```

다른 계정은 **본인 전용 Gmail과 본인 명세서 암호**를 준비합니다. 해당 계정의 ‘계정’ 화면에 표시되는 **개인 설정 번호**를 사용합니다. 예를 들어 번호가 2이면:

```text
secrets/
  users/
    2/
      gmail.json
      gmail-app-password
      statement-password
```

개인 설정이 없으면 이메일 화면에 설정 필요 상태가 나옵니다. 소유자의 Gmail이나 암호를 대신 사용하지 않습니다. 직접 업로드는 Gmail 설정 없이도 가능합니다. 두 사람이 같은 Gmail 자격 증명으로 같은 혼합 메일함을 연결하면 원본 자체를 분리할 수 없으므로, 개인 계정·개인 명세서 수신처를 사용하세요.

### NAS용 설정 도구

먼저 앱에서 공동관리자를 생성하고 상대방의 개인 설정 번호를 확인합니다. 서버 관리 터미널에서 아래 도구를 실행합니다. 비밀번호는 표시되지 않는 입력으로 받으며 명령 인자에 넣지 않습니다.

```sh
cd "$HOME/moa-projects/moa/deploy"
sudo docker compose -f compose.nas.yml --profile mail run --rm --no-deps \
  --user 0 --entrypoint python \
  -v "$PWD/secrets:/setup-secrets" \
  mail-poller scripts/configure-personal-mail.py
```

도구는 활성 공동관리자 계정을 확인한 뒤 Gmail 주소·라벨·앱 암호·본인 명세서 암호를 입력받습니다. 명세서 암호를 비우면 기존 개인 암호를 유지합니다. 삼성 공식 사이트 자동 연결은 해당 사용자의 선택으로 저장합니다. 폴더는 UID 1000·권한 700, 파일은 권한 600으로 저장합니다.

### Mac용 설정 도구

Mac에서는 기존 비밀 볼륨 안에 같은 구조를 만듭니다.

```sh
cd "$HOME/moa-projects/moa/deploy"
docker compose -f compose.nas.yml -f compose.mac.yml --profile mail run --rm --no-deps \
  --user 0 --entrypoint python \
  -v moa_mac-secrets:/setup-secrets \
  mail-poller scripts/configure-personal-mail.py
```

완료 후 해당 계정으로 로그인해 **이메일 → 목록 새로고침**을 누릅니다. 수집 프로세스는 활성 계정을 순서대로 확인하고 수집 위치·즉시 요청·암호를 따로 사용합니다. Gmail 계정의 2단계 인증과 앱 암호 준비, MOA 라벨 설정은 [Gmail 안내](../deploy/GMAIL.md)와 같습니다.

## 5. 동시 수정과 앱 복귀

개인 자료의 버전은 사용자별입니다. 상대방이 저장한 것 때문에 내 수정이 충돌하지 않습니다. 같은 계정을 두 기기·탭에서 열어 수정하면 기존처럼 먼저 저장한 내용을 보호합니다. 계정 추가·접근 변경은 공통 계정 관리 버전으로 검사합니다.

홈 화면 앱이나 브라우저로 돌아올 때 세션과 페이지를 처음 열었던 사용자를 다시 확인합니다. 같은 브라우저의 다른 탭에서 계정을 바꿨다면 개인 화면을 새로 읽습니다. 첫 화면의 사용자와 현재 세션이 다르면 API도 이전 폼의 조회·저장을 거절합니다. 확인 중인 개인 화면은 가리고, 연결이 실패하면 **다시 확인**으로 재시도할 수 있습니다. 금융 자료를 오프라인 캐시에 저장하는 기능은 여전히 제공하지 않습니다.

## 6. 개발자가 유지할 경계

- `personal_data.py`가 기존 DB 이전, 현재 사용자 범위, 통합 합계 계산을 맡습니다.
- 명세서·할부·분류 규칙·청구 설정·납부 기록에 `owner_id`가 있습니다. 거래는 소속 명세서를 통해 소유자를 확인합니다.
- 원본 단건 조회·수정·삭제도 소유권을 검사합니다. 상대방 ID와 존재하지 않는 ID는 모두 찾을 수 없음으로 처리합니다.
- `GET /api/shared-management?month=YYYY-MM`은 활성 구성원의 허용된 관리 필드만 함께 읽는 전용 API입니다. `shared_management.py`가 필드 허용 목록으로 새 응답을 만들며 원본 정보와 내부 ID를 포함하지 않습니다. 기존 개인 조회·쓰기 API의 권한은 넓히지 않습니다.
- `GET /api/household?month=YYYY-MM`은 총액·분야·카드사·월별 추이만 반환합니다. 파일명·가맹점·메모·개인별 금액·거래 ID는 넣지 않습니다.
- 메일은 사용자별 비밀 파일과 메일함 키로 분리합니다. 수집 프로세스는 환경 변수를 바꿔 끼우지 않고 작업 컨텍스트를 사용합니다.
- 기존 자료 소유권은 추측하지 않습니다. 향후 기능도 프런트엔드 필터만으로 개인 자료를 숨기지 말고 서버 조회부터 제한합니다.

실제 서버의 자료 이전은 사용자가 위 업데이트를 실행할 때 진행됩니다. 개발 환경에서는 가상 거래·기존 형식 DB·가상 Gmail·두 브라우저로 권한과 이전 실패 처리를 검증합니다.

문자 자동화의 수신 키와 임시내역도 각자 관리하며 상대방에게 공유하지 않습니다. 키에 연결된 개인에게만 저장하고 원장·통합 합계에 자동으로 더하지 않습니다. 설정은 [아이폰 문자 연결](../deploy/SMS.md)을 참고하세요.

각자의 **지출 관리 → 내 관리 → 카드값 · 명세서 → 내 카드사 추가 · 표시 이름 · 기본 결제일 설정**에서 사용 카드사를 구성합니다. 별칭·사용 여부·추가 카드사는 개인별로 저장되고, 함께 열람의 청구 목록에는 각자의 표시 이름이 보입니다. 사용 해제해도 과거 청구·할부는 보존되며 상대방 설정을 수정할 수 없습니다.


각자의 **대시보드 → 분야별 소비 패턴 → 분야 관리**에서 육아·구독료를 포함한 기본 분야 이름을 바꾸고 나만의 분야를 최대 30개 추가할 수 있습니다. 설정 목록과 수정 권한은 본인에게만 있습니다. 기존 분류 키를 유지하므로 내 과거·향후 거래에 같은 이름이 적용되고 상대방의 분류는 바뀌지 않습니다. 함께 열람의 분류 규칙과 통합 분야 합계에는 각자의 표시 이름을 적용하되 기존 허용 범위 이상의 거래·메모·분야 설정 목록은 공유하지 않습니다. 사용 중인 추가 분야는 분류를 옮긴 뒤 삭제할 수 있으며 기본 분야·미분류는 보존합니다.


신규 거래의 소비 분야 확인 상태도 본인 거래에만 연결합니다. 주황색 알림과 확인 필요 필터는 개인 화면에서만 보이고, 통합 합계·함께 열람 응답에는 확인 ID·상태·미확인 개수를 추가하지 않습니다. 확인 완료는 개인 버전과 명시적 본인 거래 ID를 검사하며 상대방 거래가 섞인 요청은 전체를 거절합니다.
