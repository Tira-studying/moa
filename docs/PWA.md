# 모아를 홈 화면 앱으로 사용하기

현재 단계는 기존 웹 화면과 서버를 활용하는 **설치형 웹앱(PWA)**입니다. 앱스토어·Play 스토어에 등록한 네이티브 앱은 아닙니다. 서버는 현재 NAS 또는 이전한 Mac에서 계속 실행됩니다.

## 1. 이번에 추가한 기능

- 모아 전용 홈 화면 아이콘과 앱 이름
- 지원 기기에서 주소창 없이 열리는 독립 실행 화면
- 로그인 화면과 ‘계정’ 화면의 설치 안내
- 브라우저가 설치 기능을 제공하면 사용자 클릭으로 여는 설치 버튼
- 인터넷·Tailscale·서버 연결이 끊겼을 때 보여주는 고정 안내
- 앱으로 복귀할 때 로그인 만료·계정 접근 해제·다른 탭의 계정 전환 확인

기존 거래·명세서 업로드·분류·납부 기록을 개인 범위로 관리하고 통합 합계만 공유합니다. 복귀 시 사용자 확인이 끝나기 전에는 개인 화면을 가리고, 계정이 바뀌면 새 계정의 화면을 다시 읽습니다. 생체 인증·푸시 알림·다른 앱에서 명세서 공유받기·오프라인 거래 편집은 이번 단계에 포함하지 않습니다.

## 2. 서버 업데이트

### NAS를 계속 사용하는 경우

기존 SSH 배포 키 방식에서는 NAS 터미널에서 실행합니다.

```sh
cd "$HOME/moa-projects"
sudo docker run --rm -it \
  -v "$PWD":/git -w /git/moa \
  -v moa-git-ssh:/root/.ssh \
  alpine/git pull --ff-only origin main
cd moa/deploy
sudo docker compose -f compose.nas.yml --profile mail up -d --build app mail-poller
```

### Mac 이전이 끝난 경우

Mac 터미널에서 기존 Mac 추가 설정을 함께 사용합니다.

```sh
cd "$HOME/moa-projects/moa"
git pull --ff-only origin main
cd deploy
docker compose -f compose.nas.yml -f compose.mac.yml --profile mail up -d --build app mail-poller
```

메일 수집을 사용하지 않는 설치에서는 `--profile mail`과 `mail-poller`를 빼면 됩니다. 데이터·Tailscale 볼륨을 새로 만들거나 로그인 계정을 다시 초기화할 필요는 없습니다.

업데이트 후 브라우저에서 모아를 새로 열거나 새로고침합니다. 서비스 워커 갱신이 진행되어도 입력 중인 화면을 강제로 새로고침하지 않습니다.

## 3. 아이폰·아이패드에 설치

1. Tailscale을 연결합니다. 공동관리자는 먼저 본인 계정으로 moa-card 공유 초대를 수락해야 합니다.
2. **Safari**에서 기존 HTTPS 주소를 엽니다. 주소는 `https://moa-card.YOUR-TAILNET.ts.net` 형태입니다.
3. Safari 공유 메뉴에서 **홈 화면에 추가**를 선택합니다.
4. **웹 앱으로 열기**가 보이면 켜고 추가합니다. 메뉴 위치와 명칭은 iOS 버전에 따라 다를 수 있습니다.
5. 홈 화면의 **모아** 아이콘으로 엽니다. 설치된 앱에서 별도로 로그인해야 할 수 있습니다.

홈 화면 앱도 기존 모아 아이디·비밀번호를 사용합니다. 계정이나 데이터가 기기마다 새로 생기는 방식이 아닙니다.

## 4. 안드로이드에 설치

1. Tailscale을 연결하고 **Chrome**에서 기존 HTTPS 주소를 엽니다.
2. 로그인 화면 또는 **계정 → 휴대폰 홈 화면에 설치**를 펼칩니다.
3. **모아 설치** 버튼이 보이면 누릅니다. 버튼은 브라우저가 설치 가능하다고 알린 경우에만 표시합니다.
4. 버튼이 없으면 Chrome 메뉴의 **앱 설치** 또는 **홈 화면에 추가**를 사용합니다.
5. 홈 화면 아이콘으로 실행해 로그인합니다.

브라우저의 설치 조건·버전·기존 설치 상태에 따라 메뉴가 달라질 수 있습니다. 설치 창을 취소해도 웹 화면은 계속 사용할 수 있습니다.

## 5. 인터넷과 Tailscale은 계속 필요합니다

PWA 설치는 접속 방법을 바꾸는 것이지 서버를 휴대폰으로 옮기는 것이 아닙니다. 현재 구성에서는 인터넷, Tailscale 연결, NAS·Mac의 모아 실행 상태가 모두 필요합니다. 공개 HTTPS 접속을 별도로 구성한다면 그 접속 정책에 맞춰 안내도 변경해야 합니다.

연결이 끊긴 상태에서 앱을 새로 열면 ‘모아에 연결할 수 없어요’라는 안내가 나옵니다. 연결을 복구한 뒤 **다시 연결하기**를 누릅니다. API 요청·업로드·저장을 오프라인 대기열에 넣거나 성공한 것처럼 처리하지 않습니다.

이미 화면에 표시된 내용은 페이지가 열린 동안 메모리에 남을 수 있습니다. 이 기능이 휴대폰 운영체제의 앱 미리보기나 스크린샷까지 차단하는 것은 아닙니다.

## 6. 금융 자료를 캐시하지 않는 방식

서비스 워커는 브라우저가 페이지와 별도로 실행하는 작은 프로그램입니다. 모아에서는 연결 실패 안내를 제공하는 데만 사용합니다.

| 항목 | PWA가 하는 처리 |
| --- | --- |
| 고정 연결 안내 `/static/offline.html` | 개인정보 없는 파일 하나만 Cache Storage에 저장 |
| `/`, `/login`, 사용 내역 화면 | 매번 서버에 요청하고 서비스 워커 캐시에 저장하지 않음 |
| `/api/…` | 가로채거나 캐시하지 않음 |
| 명세서 원본·해제 결과·업로드 요청 | 캐시하거나 오프라인 재전송하지 않음 |
| 거래·비밀번호·로그인 토큰 | Local Storage·Session Storage·IndexedDB에 쓰지 않음 |
| 로그인 쿠키 | 기존 보안 쿠키·서버 세션 방식을 유지 |

기존 서버 응답의 `Cache-Control: no-store`, 로그인·권한 검사, 세션 만료(기본 8시간, 로그인 유지는 90일·사용 시 연장), 공동 수정 버전 검사를 유지합니다. PWA의 안내 캐시와 브라우저·OS가 관리하는 일반 로그인 쿠키·홈 화면 아이콘 저장은 서로 다른 기능입니다.

앱으로 복귀해 사용자 확인을 기다리는 동안 본문과 금융 대화상자를 함께 가립니다. 계좌 출금 정리 폼의 사용처·메모도 확인 전에는 표시하지 않으며, 계정이 바뀌면 기존처럼 새 페이지로 이동합니다.

## 7. 개발자가 읽을 파일

`connection-setup.js`의 금융 인증 입력도 브라우저 저장소나 캐시에 넣지 않습니다. 전송·화면 이동·백그라운드 전환·pagehide 시 입력을 비웁니다. SMS 앱에서 복귀하거나 새로고침하면 현재 로그인 세션에 결합된 작업 상태만 읽어 이어가고, 로그인·인증 답변을 자동 재전송하지 않습니다. 기존 본문 가림 정책은 연결 화면에도 적용됩니다.

| 파일 | 역할 |
| --- | --- |
| `static/manifest.webmanifest` | 설치 이름·실행 경로·아이콘·standalone 설정 |
| `static/pwa.js` | 설치 안내·설치 버튼·연결 상태·복귀 시 세션 확인 |
| `static/sw.js` | 네트워크 우선 페이지 이동과 고정 안내만 저장하는 서비스 워커 |
| `static/offline.html` | 계정·거래 정보 없는 독립 연결 안내 |
| `static/pwa.css` | 설치 안내·연결 표시·화면 상단 안전 영역 |
| `static/icons/` | Android 192/512 및 Apple 180 픽셀 아이콘 |
| `scripts/generate-pwa-icons.py` | 가상 카드 모양으로 아이콘을 다시 만드는 도구 |
| `app.py`의 `pwa_service_worker` | `/sw.js`를 앱 루트 범위에서 제공 |
| `tests/test_pwa.py`, `tests/pwa-ui.cjs` | 설치 자원·로그인 경계·실제 오프라인 캐시와 세션 복귀 검증 |

서비스 워커와 설치 자원은 로그인 전에도 받을 수 있어야 하지만 실제 금융 API의 인증을 우회하면 안 됩니다. 공개 서비스 워커 경로에도 기존 HTTPS·호스트 검사를 적용합니다.

`offline.html`을 바꾸면 `sw.js`의 `CACHE_NAME` 버전을 올려 새 안내를 설치합니다. 캐시 정책을 바꿀 때는 금융 응답이 저장되지 않는 테스트를 먼저 확인합니다. 서버의 정적 파일 응답도 `no-store`로 설정되어 있지만, 서비스 워커의 명시적인 Cache Storage 저장은 별개이므로 저장 대상을 늘리지 않습니다.

아이콘을 다시 만들려면 기존 Python 의존성이 설치된 환경에서 실행합니다.

```sh
.venv/bin/python scripts/generate-pwa-icons.py
```

## 8. 검증 범위와 다음 단계

자동 검증은 실제 Chromium 서비스 워커와 임시 DB의 가상 거래를 사용합니다. 고정 안내만 캐시에 있는지, 오프라인 금융 API가 실패하는지, 연결 복구 후 서버 화면이 나오는지, 로그아웃된 세션으로 복귀하면 로그인으로 이동하는지 확인합니다. Safari 설치 안내와 Chrome 설치 버튼 이벤트도 검증합니다.

실제 iOS·Android의 홈 화면 추가·기기별 앱 전환·파일 선택은 각 기기에서 최종 확인해야 합니다. 브라우저 이벤트를 흉내 낸 테스트는 운영체제의 실제 설치를 대신하지 않습니다. 이 개발 환경에서는 실제 휴대폰 설치와 Mac 기기 실행까지 확인하지 않았습니다.

이후에는 모바일 파일 공유 흐름을 설계하고 필요에 따라 Capacitor 앱으로 확장할 수 있습니다. 현재 API는 같은 HTTPS 출처의 웹앱과 보안 쿠키를 기준으로 합니다. 네이티브 앱으로 확장할 때는 인증·출처·기기별 세션 정책을 따로 검토해야 하며, 단순히 기존 출처 검사를 해제하는 방식으로 연결하지 않습니다.
