# 서로 다른 Tailscale 계정으로 공동 관리

모아는 소유자 1명과 활성 공동관리자 1명이 각자 개인 원장을 관리하고 통합 지출 합계와 허용된 관리 정보를 함께 열람합니다. Tailscale 계정과 모아 계정은 서로 별개이며, Tailscale만 연결해도 모아 로그인이 필요합니다. 원본 명세서·일반 거래 목록·메모는 비공개입니다. 분류 규칙·할부·중복 검토·고정 지출·청구·납부·결제일은 함께 열람하고 수정은 본인만 가능합니다. 상세 권한과 업데이트 전 백업은 [개인 관리와 통합 공유 안내](../docs/PERSONAL_SHARING.md)를 먼저 확인하세요.

## 1. NAS 앱 업데이트

기존 설치의 DB와 Tailscale 상태 볼륨을 유지합니다. 기존 소유자 비밀번호는 그대로 사용하며 **아이디는 `owner`**입니다. 개인 관리 구조로 이전할 때는 기존 세션을 종료하므로 다시 로그인해야 합니다. 업데이트 시 별도 계정 초기화 명령은 필요하지 않습니다.

SSH 배포 키를 사용하던 NAS에서는:

```sh
cd "$HOME/moa-projects"
sudo docker run --rm -it \
  -v "$PWD":/git -w /git/moa \
  -v moa-git-ssh:/root/.ssh \
  alpine/git pull --ff-only origin main
cd moa/deploy
sudo docker compose -f compose.nas.yml --profile mail up -d --build app mail-poller
```

앱이 기존 DB에 사용자·변경 이력·공동 수정 확인용 테이블을 추가합니다. `docker compose down -v`로 볼륨을 삭제하지 마세요. 메일 수집을 사용하지 않는 설치는 `--profile mail`과 `mail-poller`를 빼면 됩니다.

## 2. 모아 공동관리자 계정 만들기

1. 모아에 소유자로 로그인합니다. 새 로그인 화면의 아이디는 `owner`, 비밀번호는 기존 것 그대로입니다.
2. 상단 **계정 → 공동관리자 계정 추가**에서 상대방 아이디와 초기 비밀번호를 입력합니다. 아이디는 영문 소문자·숫자·밑줄·하이픈 3~40자이고 비밀번호는 12~128자입니다.
3. 상대방에게 주소·아이디·초기 비밀번호를 안전하게 전달합니다. Tailscale 장치 공유 초대는 다음 단계에서 별도로 전달합니다.
4. 공동관리자는 첫 로그인 후 **계정 → 내 비밀번호 변경**에서 본인 비밀번호로 바꿉니다. 변경하면 해당 계정의 모든 기기에서 로그아웃되므로 다시 로그인합니다.

소유자만 공동관리자를 추가하거나 접근 해제·재허용, 비밀번호 재설정을 할 수 있습니다. 접근 해제와 재설정은 해당 계정의 기존 세션을 모두 폐기합니다. 해제한 계정은 이력 보존을 위해 삭제하지 않습니다. 활성 공동관리자는 1명까지이고 해제한 다른 계정 대신 새 계정을 추가할 수 있습니다.

공동관리자는 본인의 명세서 열기·저장·삭제, 분류·메모 수정, 중복 제외·복원, 할부와 월별 납부 기록을 관리합니다. 함께 열람 화면에서 허용된 관리 정보를 확인할 수 있지만 상대방 자료의 수정·삭제는 하지 못합니다. Gmail/공통 명세서 비밀번호는 NAS의 기존 비밀 파일을 그대로 사용하며 앱에서 비밀번호 원문을 보여주거나 변경하는 API는 제공하지 않습니다. NAS의 SSH·Docker·비밀 파일 접근 권한은 공동관리자에게 전달하지 않습니다.

## 3. Tailscale의 moa-card 장치만 공유

공동관리자를 내 tailnet 전체의 구성원으로 초대할 필요는 없습니다. **장치 공유**를 사용합니다.

1. 소유자의 [Tailscale 관리 화면](https://login.tailscale.com/admin/machines)에서 **Machines** 목록을 엽니다.
2. 앱용 장치 **`moa-card`**를 찾아 메뉴의 **Share / Share machine**에서 초대 링크를 만듭니다. 메뉴 이름과 공유 가능 여부는 계정 정책에 따라 다를 수 있습니다.
3. 해당 상대방에게만 링크를 전달합니다. 상대방은 자신의 Tailscale 계정으로 로그인한 상태에서 링크를 수락합니다. 소유자 계정으로 로그인할 필요가 없습니다.
4. 상대방의 아이폰·아이패드에 Tailscale을 설치하고 **초대를 수락한 계정**으로 로그인한 뒤 연결을 켭니다.
5. Safari에서 기존 모아의 **전체 HTTPS 주소**를 엽니다. 주소는 `https://moa-card.YOUR-TAILNET.ts.net` 형태이며, `tailscale serve status`에 표시되는 주소를 사용합니다. 짧은 장치 이름이나 IP 대신 전체 주소를 사용해야 HTTPS 인증서와 앱의 주소 검사가 맞습니다.
6. **모아 공동관리자 아이디·비밀번호**로 로그인합니다.

NAS 본체 장치(`my-nas` 등), SSH·Tailscale 관리자 권한, 소유자 계정은 공유 대상이 아닙니다. 앱의 기존 userspace Tailscale 컨테이너와 Serve 구성을 그대로 사용합니다. 공유기 포트 개방이나 Funnel로 공개할 필요가 없습니다.

## 4. 접속 정책과 확인

모아 접속에는 공유한 **moa-card의 TCP 443(HTTPS)** 허용이 필요합니다. 기존 tailnet 접근 정책이 공유 사용자를 제한한다면 소유자가 Access controls에서 해당 장치와 포트만 허용해야 합니다. NAS 본체나 모든 장치에 대한 허용을 추가하지 않습니다. 장치 공유도 기존 접근 정책의 영향을 받습니다.

기존 정책이 `grants`를 사용하는 경우, 정책 편집자가 아래 형태를 참고해 **실제 moa-card의 Tailscale IPv4 주소로 바꿔 기존 grants 배열에 규칙을 병합**할 수 있습니다. 정책 전체를 교체하는 예제가 아닙니다.

```json
{
  "src": ["autogroup:shared"],
  "dst": ["100.64.0.10"],
  "ip": ["tcp:443"]
}
```

예시 IP는 그대로 사용하지 않습니다. 실제 IP는 Tailscale Machines 화면 또는 NAS에서 아래 명령으로 확인합니다.

```sh
cd "$HOME/moa-projects/moa/deploy"
sudo docker compose -f compose.nas.yml exec tailscale tailscale ip -4
sudo docker compose -f compose.nas.yml exec tailscale tailscale serve status
```

`autogroup:shared`는 공유받은 사용자를 나타냅니다. 이 허용 규칙은 기존의 더 넓은 허용을 취소하지 않으므로, 정책 편집기에서 기존 규칙과 허용 범위도 함께 확인합니다. 공유한 장치의 IP가 바뀌면 IP를 지정한 규칙도 갱신합니다. 조직이 장치 공유를 금지했다면 해당 정책 관리자의 설정이 필요합니다.

상대방 기기의 Wi-Fi를 끄고 LTE/5G + Tailscale 연결 상태에서 모아 로그인을 확인합니다. 장치는 보이지만 사이트가 열리지 않으면 **초대 수락 계정 → Tailscale 연결 → 전체 HTTPS 주소 → 공유 장치의 TCP 443 정책 → Serve 상태** 순서로 확인합니다. 사이트는 열리지만 로그인에 실패하면 모아 아이디·비밀번호와 활성 여부를 확인합니다. 두 서비스의 비밀번호는 별개입니다.

공식 안내: [장치 공유](https://tailscale.com/kb/1084/sharing), [Tailscale Serve](https://tailscale.com/kb/1242/tailscale-serve).

이 업데이트가 실제 Tailscale 초대를 만들거나 정책을 변경하지는 않습니다. 소유자가 관리 화면에서 공유하고 상대방이 수락해야 합니다. 개발 환경에서는 서로 다른 실제 Tailscale 계정의 접속까지 검증하지 않았습니다.

## 5. 변경 이력과 동시 수정

**계정 → 내 변경 이력 · 계정 관리 이력**에서 기능 적용 이후의 작업자·시각·변경 종류·대상을 최근 100건 확인합니다. 본인의 명세서 저장/삭제, 거래 분류·상세, 할부, 중복 제외/복원, 고정 지출 확인, 납부 기록과 공동 계정 변경을 기록합니다. 상대방의 개인 이력은 조회하지 않습니다. 메일 조회·첨부 열기와 자동 수집 상태 갱신은 거래 변경 이력에 포함하지 않습니다. 비밀번호·원본 파일·메모·거래 본문을 이력에 복제하지 않습니다.

저장은 서버의 SQLite 트랜잭션 안에서 개인 원장 또는 계정 관리 버전을 확인합니다. 다른 화면이 먼저 변경했다면 저장을 거절하고 기존 입력을 유지합니다. 화면에 표시된 안내에 따라 입력 내용을 확인한 후 **최신 화면 다시 열기**로 갱신하세요. 다시 열면 저장하지 않은 입력은 초기화되며, 변경 사항을 다시 검토해 저장합니다. 같은 계정의 다른 화면이 자료를 바꾸면 재확인을 요청합니다. 개인 원장 버전은 사용자별로 구분하므로 상대방의 개인 저장과 충돌하지 않습니다. 계정 관리는 별도 공통 버전으로 검사합니다. 같은 계정으로 여러 기기를 사용할 때도 적용됩니다.

새 웹 화면은 항상 버전을 전송합니다. 공동관리자가 활성화된 뒤에는 버전이 없는 구버전의 저장 요청도 거절합니다. 오래 열린 브라우저는 업데이트 후 새로고침합니다. 로그인·로그아웃은 버전과 관계없이 가능하며, 비밀번호 변경이나 접근 해제 시에는 해당 계정의 세션을 검사해 접근을 차단합니다.

기존 `python manage.py` 방식으로 소유자 비밀번호를 복구하면 모든 계정의 세션을 종료합니다. 공동관리자 계정과 카드 내역은 유지됩니다.

## 6. 공유 종료

1. 모아 소유자 계정으로 **계정 → 해당 공동관리자 → 접근 해제**를 누릅니다. 이미 로그인한 상대방도 이후 요청부터 차단됩니다.
2. Tailscale 관리 화면에서 해당 상대방의 **moa-card 공유도 제거**합니다. 모아에서 계정을 해제하는 것과 별개입니다.

각 서비스에서 접근을 해제해도 이미 상대방이 열거나 내려받은 자료까지 회수되지는 않습니다.
