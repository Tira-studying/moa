# CODEF 데모 키 설정과 실제 조회 검증

**데모 키 설정·개발자 토큰 확인**과 **NAS 터미널에서 삼성·현대·KB국민·신한·롯데·우리카드 최근 7일 승인내역을 수동 조회하는 시험**을 제공합니다. 이 안내의 `verify-codef-card.py` 일회성 시험은 연결·지출을 저장하지 않습니다. 계정 등록 없이 수동으로 지출도 저장하려면 [직접 조회·저장 안내](CODEF_AUTO.md#계정-등록-없이-수동-조회저장하기)의 `--direct` 명령을 사용합니다. 개인 연결과 매일 한국시간 00:00·08:00·14:00·20:00 자동 수집을 시작하려면 [자동 수집 안내](CODEF_AUTO.md)를 따릅니다.

사용할 값은 CODEF 화면의 **데모버전 client_id·client_secret**과 위쪽 **public_key**입니다. 샌드박스·운영 키와 섞지 마세요. 데모 API 주소는 `https://development.codef.io`입니다. 개발자 인증 확인은 CODEF의 고정 OAuth 주소에만 연결하며 토큰을 받더라도 실제 카드 조회 권한·무료 한도가 확인된 것은 아닙니다.

## 1. NAS에서 최신 코드 받기

Git 대신 기존 Git 컨테이너를 쓰는 NAS 설치 기준입니다. Git SSH 키 볼륨 이름이 기존 설치와 다르면 원래 이름을 사용합니다.

```sh
cd "$HOME/moa-projects"
sudo docker run --rm -it \
  -v "$PWD":/git -w /git/moa \
  -v moa-git-ssh:/root/.ssh \
  alpine/git pull --ff-only origin main
cd moa/deploy
sudo docker compose -f compose.nas.yml --profile mail up -d --build app mail-poller
```

## 2. NAS에서 키 입력

같은 `moa/deploy` 폴더에서 실행합니다. 키를 명령문에 직접 붙여 넣지 않습니다.

```sh
sudo docker compose -f compose.nas.yml run --rm --no-deps \
  --user 0 \
  -v "$PWD/secrets:/setup-secrets" \
  app python scripts/configure-codef.py
```

다음 순서로 질문이 나오면 CODEF 화면에서 각각 복사해 붙여 넣고 Enter를 누릅니다.

1. `데모 client_id`
2. `데모 client_secret`
3. `public_key` — 복사 버튼으로 받은 base64 공개키 한 줄

**입력 중 글자가 보이지 않는 것이 정상입니다.** 각 항목을 입력하면 `client_id 형식: 정상`처럼 형식 검사 결과만 표시합니다. 실제 CODEF 인증 성공 여부는 다음 단계에서 확인합니다. 잘못 복사한 항목은 해당 항목만 다시 입력받고 앞서 정상 입력한 값을 다시 요구하지 않습니다. 정상 저장 문구가 나오면 키 설정을 마친 것입니다. 검증이나 파일 교체에 실패하면 기존 설정은 보존합니다.

기존 읽기 전용 마운트의 폴더 안에 파일을 추가·교체하므로 정상 설치에서는 앱을 다시 시작할 필요가 없습니다. 설정 화면에서 ‘설정 상태 새로고침’을 누릅니다.

## 3. 모아에서 연결 확인

1. **소유자 계정**으로 로그인합니다.
2. **계정 → CODEF 데모 개발자 인증**을 펼칩니다.
3. **설정 상태 새로고침**을 눌러 버튼이 활성화되는지 확인합니다.
4. **개발자 인증 확인**을 누릅니다.

‘CODEF 개발자 토큰 발급에 성공했습니다’가 나오면 호출용 인증을 확인한 것입니다. **실제 카드사 로그인·카드 거래 조회까지 성공한 상태는 아닙니다.** 다음의 수동 시험으로 확인합니다. 카드사 비밀번호나 카드 PIN·인증번호는 개발자 키 설정 도구에 넣는 값이 아닙니다.

확인은 수동 버튼으로만 실행하고 같은 설정에서는 1분에 한 번으로 제한합니다. 페이지 열기·설정 새로고침만으로 CODEF 요청이 발생하지 않습니다. 토큰을 반복 저장하거나 재사용하지 않는 연결 시험이므로 초기 설정 검증 후 반복해서 누를 필요는 없습니다.

## 4. 카드사별 실제 승인·취소 조회 시험

1번의 최신 코드 받기·앱 빌드를 먼저 완료합니다. 기존 CODEF 키를 다시 입력할 필요는 없습니다. 같은 `moa/deploy` 폴더에서 실행하세요.

```sh
sudo docker compose -f compose.nas.yml run --rm --no-deps \
  app python scripts/verify-codef-card.py --card samsung
```

이 명령은 삼성카드를 조회합니다. 인자 없이 실행해도 삼성카드가 기본값이며, KB국민은 `--card kb`를 사용합니다. 현대카드는 다음 명령을 사용합니다.

```sh
sudo docker compose -f compose.nas.yml run --rm --no-deps \
  app python scripts/verify-codef-card.py --card hyundai
```

신한·롯데·우리카드는 같은 명령에서 `--card` 뒤 이름을 다음처럼 지정합니다. 한 번 실행할 때 선택한 카드사 한 곳만 조회합니다.

| 카드사 | 선택 인자 |
| --- | --- |
| 삼성 | `--card samsung` (기본값) |
| 현대 | `--card hyundai` |
| KB국민 | `--card kb` |
| 신한 | `--card shinhan` |
| 롯데 | `--card lotte` |
| 우리 | `--card woori` |

예를 들어 신한카드는 다음을 실행하고 **신한카드 홈페이지 아이디·비밀번호**를 입력합니다. 롯데·우리도 해당 홈페이지 로그인 정보를 사용합니다.

```sh
sudo docker compose -f compose.nas.yml run --rm --no-deps \
  app python scripts/verify-codef-card.py --card shinhan
```

롯데는 홈페이지 로그인 입력 다음에 카드사에 등록된 본인 이름을 숨겨 입력받아 `userName`으로 전송합니다. `CF-12851` 사용자 이름 누락에 대응하는 입력이며 이름을 저장하거나 출력하지 않습니다. 본인 이름 다음에 `identity`도 숨겨 입력받습니다. 제공 명세대로 **생년월일 6자리 + 주민번호 뒷자리 첫 숫자의 7자리**만 전송하며 전체 주민번호는 받지 않습니다. 값은 TLS로 CODEF에 전송하고 저장·출력하지 않습니다. 13자리 입력을 자동으로 잘라 전송하지 않고 로컬에서 거부합니다. 이어서 본인 명의 휴대폰번호(`phoneNo`)와 통신사(`telecom`)를 숨겨 입력받습니다. 통신사 코드는 제공 명세대로 0 SKT, 1 KT, 2 LG U+, 3 알뜰폰 SKT망, 4 알뜰폰 KT망, 5 알뜰폰 LG U+망입니다. 번호의 하이픈·공백만 제거하며 10~11자리 국내 휴대폰 형식을 검사합니다. 번호·통신사도 메모리에서 CODEF 전송에만 사용하고 저장·출력하지 않습니다. 지원하는 문자/이메일 인증번호·휴대폰 승인 외의 추가 인증이 나오면 중단하며 표시된 오류 코드로 다음 지원 범위를 확인합니다. 우리카드는 문서에 따라 가맹점 상세 옵션을 `0`으로 유지합니다. 신한·롯데 부분취소도 금액을 추정해 합산하지 않고 건수만 표시합니다.

### 롯데 SMS 추가 인증 이어가기

첫 요청에 `CF-03002`와 `continue2Way: true`가 오면 문자 인증번호 입력 안내가 나옵니다. 받은 번호를 NAS 또는 Mac의 숨김 입력란에 넣습니다. 인증번호는 채팅에 보내지 않습니다. 입력 순서는 홈페이지 아이디 → 비밀번호 → 본인 이름 → 본인 확인용 7자리 → 휴대폰번호 → 통신사이며, SMS 번호는 CODEF가 추가 인증을 요청한 다음에 입력합니다.

도구는 원래 조회 요청에 `is2Way: true`, `smsAuthNo`, `twoWayInfo`를 더해 같은 API로 요청합니다. `twoWayInfo`에는 해당 응답의 `jobIndex`, `threadIndex`, `jti`, `twoWayTimestamp`만 값을 바꾸지 않고 넣습니다. 인덱스가 `0`이어도 유효하게 유지하며, 연결 정보가 하나라도 없으면 번호를 요구하거나 전송하지 않습니다. 롯데 응답에 `commSession`도 있으면 후속 인증 요청에 함께 전달합니다. 다음 단계가 이 값을 생략해도 직전 세션을 메모리에서 유지하며 새 값이 오면 교체합니다. 번호와 연결 정보는 파일·DB·로그에 저장하지 않습니다.

제공된 롯데 규격은 `method`를 필수로 명시하지 않으므로, 롯데 기관코드 `0311`의 위 응답에서 `method`가 없거나 비어 있어도 SMS로 이어갑니다. 다른 카드사에 이를 적용하거나 명시된 알 수 없는 인증 방식을 SMS로 바꾸지는 않습니다. `continue2Way`가 false이거나 문자열이면 진행하지 않습니다. 문자 인증번호는 숫자만 허용하며 잘못 입력한 문자를 자동 전송하지 않습니다. 추가 인증은 기존대로 최대 3단계이며, 로그인 실패·잘못된 인증번호 응답을 자동 재시도하지 않습니다.

현대는 홈페이지 아이디·비밀번호 외에 **전체 카드번호와 카드 비밀번호 4자리**가 필요합니다. 카드번호는 TLS 연결로, 카드 비밀번호는 RSA 암호화해 CODEF로 전송하며 저장하거나 출력하지 않습니다. 카드 비밀번호 3회 오류 시 이용이 제한될 수 있으므로 확실하지 않으면 Ctrl+C로 중단합니다. 오류 시 자동 재시도하거나 삼성으로 자동 전환하지 않습니다.

여기에는 `-T`를 붙이지 않습니다. 대화형 터미널에서 다음을 입력합니다. **입력하는 동안 글자가 표시되지 않는 것이 정상입니다.**

1. **선택한 카드사의 홈페이지 로그인 아이디**
2. **선택한 카드사의 홈페이지 로그인 비밀번호** — 명세서 파일 암호·카드 PIN과 다릅니다.
3. 추가 인증이 요구되면 문자/이메일 인증번호를 입력하거나 휴대폰 인증을 승인한 뒤 Enter를 누릅니다.

홈페이지 비밀번호는 RSA로 암호화하고 아이디는 TLS 연결로 CODEF 데모 서버에 전송합니다. 별도 계정 등록 없이 직접 로그인하며 연결 ID·카드사 비밀번호·토큰·응답을 파일이나 DB에 저장하지 않습니다. 기존 앱과 Gmail 작업자는 계속 실행됩니다. 조회 중 수 분 걸릴 수 있으며 로그인 실패나 통신 실패를 자동 재시도하지 않습니다. 추가 인증을 이어가는 요청만 최대 3회 허용합니다.

성공하면 한국시간 기준 오늘을 포함한 최근 7일의 **전체·승인·취소·부분취소·거절·확인 필요 건수**를 표시합니다. 같은 기간 선택한 카드사 앱의 **전체 카드** 내역과 비교하세요. 0건도 정상 응답일 수 있습니다. ‘확인 필요’가 있거나 건수가 다르면 완전 수집으로 보지 않습니다. 부분취소·음수 금액의 순지출 계산은 이 단계에서 하지 않습니다. 조회 성공이 정기 수집·지출 저장을 시작한다는 뜻은 아닙니다.

- `CF-04000`: 일반적인 계정 등록 실패입니다. 이 코드만으로 아이디·비밀번호가 틀렸다고 단정하거나 다시 입력받지 않습니다. 등록 없이 수동 조회·저장이 필요한 경우 아래 `--direct` 경로를 확인합니다.
- `CF-04034`: 롯데 추가 인증 안내가 있어도 실제 `continue2Way: true`와 네 연결 정보가 없으면 중단합니다. 문자 도착만으로 재개 정보를 만들거나 같은 번호를 다른 요청에 붙이지 않습니다. 직접 조회에서도 같은 응답이 나오면 CODEF의 추가 인증 규격 확인이 필요합니다.
- `CF-12401`: 로그인 파라미터 누락입니다. 응답에 언급된 키 중 알려진 이름만 표시합니다. `phoneNo`·`telecom` 같은 키 이름만 공유하고 원문·입력값은 보내지 않습니다. 알려진 키가 없으면 확인 불가로 표시하며 원인을 추측하지 않습니다.
- `CF-12850`: 본인 확인 정보 누락입니다. 롯데는 최신 도구에서 위의 `identity` 7자리를 입력합니다. 제공된 오류 표의 과금유무가 O이므로 반복 시험을 줄이고 이용 계약의 과금 조건을 확인합니다.
- `CF-12851`: 사용자 이름 누락입니다. 최신 도구에서 롯데카드에 등록된 본인 이름을 입력하세요.
- `CF-12108`: KB 카드 소지 확인이 필요한 경우입니다. 현재 도구는 카드번호·PIN을 추가로 요구하지 않고 중단합니다. 오류 코드만 전달해 주세요.
- `CF-03002`: 지원하지 않는 추가 인증이거나 인증 단계를 완료하지 못한 경우입니다. 원문·인증번호 대신 표시된 고정 안내만 전달하세요.
- HTTP 인증/상품 권한 안내: CODEF 계정의 데모 승인내역 상품 이용 권한을 확인합니다. 개발자 토큰 성공과 실제 카드 조회 권한은 별개입니다.
- 그 밖의 오류: 표시된 `CF-숫자 5자리` 코드와 고정 안내만 확인합니다. 카드사 로그인 실패를 반복 실행하지 마세요.
- `CF-12834`: 카드 비밀번호 오류로 이용이 제한된 경우입니다. 재시도하지 말고 카드사에서 확인하세요.

### 홈페이지 로그인은 되지만 CF-12800이 나오는 경우

[공식 오류표](https://developer.codef.io/common-guide/error-code)에서 `CF-12800`은 아이디 오류, `CF-12831`은 본인 인증 후 이용 가능으로 확인했습니다. 전자는 홈페이지 아이디를 확인하고, 후자는 홈페이지의 본인 인증 안내를 확인합니다. 비밀번호 오류로 확대 해석하거나 자동 재시도하지 않습니다. 홈페이지와 CODEF 서버의 로그인 환경은 다를 수 있습니다. 최신 도구는 오류 코드 옆에 **응답 안내 주제**를 표시합니다. 공급자 `message/extraMessage`는 메모리에서 키워드만 확인하며, 실제 이름·아이디·전화번호 등이 섞일 수 있는 원문은 출력하거나 저장하지 않습니다.

홈페이지 로그인이 정상임을 확인했다면 최신 코드로 업데이트한 뒤 선택 카드사의 시험을 **한 번만** 실행하고 코드와 주제 안내만 확인합니다. 이는 이미 실행한 조회의 원문을 복원하는 기능이 아니라 새 조회 요청이므로 반복 실행하지 않습니다. 보안문자·추가 인증·접속 제한 등의 안내가 나오면 해당 흐름의 지원 여부를 확인합니다. ‘로그인·계정 정보’도 비밀번호가 틀렸다는 확정 판정은 아닙니다. 분류 불가라면 홈페이지 로그인 정상 여부와 API 경로·기관코드·오류 코드·실행 시각으로 CODEF 지원에 문의합니다. 비밀번호·토큰·원본 응답은 공유하지 않습니다.

### 한글 이름 입력 중 UTF-8 오류가 나오는 경우

이름을 입력하자마자 `utf-8 codec can't decode` 오류로 끝났다면 카드사 조회를 보내기 전 터미널 입력에서 실패한 경우입니다. 이것은 이름을 영문으로 바꾸라는 뜻이 아닙니다. 최신 코드를 받고 앱 이미지를 다시 빌드한 뒤 등록된 이름을 입력하세요. 모바일 SSH에서 한글을 지우거나 조합할 때 문자가 깨질 수 있으므로 이름을 복사해 **한 번에 붙여 넣고 Enter**를 누르는 방법도 사용할 수 있습니다.

최신 도구는 Linux 터미널의 UTF-8 지우기 설정(IUTF8)을 입력 동안 켜고 종료 시 복원합니다. 깨진 문자는 잘못된 이름으로 변환해 전송하지 않고, 예외 원문이나 입력값을 표시하지 않은 채 해당 항목만 최대 세 번 다시 받습니다. 숨김 입력이 불가능한 터미널에서는 표시 입력으로 전환하지 않고 중단합니다. 실제 NAS 터미널에서 계속 실패한다면 인코딩 오류 안내만 공유하고 이름·비밀번호는 보내지 마세요.

### 이름 입력 안내가 나오고 조회 전에 끝나는 경우

휴대폰·통신사 입력 뒤 ‘롯데카드에 등록된 본인 이름을 입력해 주세요’로 끝났던 구버전은 모든 입력을 받은 뒤 이름을 검사했습니다. CODEF 오류가 아니라 로컬 검사에서 중단된 것이므로 해당 실행에서는 조회를 보내지 않은 상태입니다. 볼륨 경고와도 별개의 문제입니다.

최신 도구는 이름을 입력하자마자 검사합니다. 빈 입력과 형식을 읽지 못한 입력을 구분해 안내하고 이름만 최대 세 번 다시 받습니다. ‘이름 입력 형식: 정상’을 확인한 뒤 본인 확인용 7자리·휴대폰·통신사를 입력합니다. 이 안내는 카드사 등록 이름과 일치한다는 뜻은 아닙니다. 입력이 반복해서 비어 있으면 등록된 이름을 복사해 한 번에 붙여 넣고 Enter를 누르세요.

붙여넣기 앞뒤의 공백·줄바꿈·BOM·제로폭 공백만 제거하고 한글을 NFC 조합형으로 맞춥니다. 이름 내부의 공백과 성·이름 순서는 보존하며, 내부 제어 문자는 임의로 지워 전송하지 않습니다. 실제 이름과 입력 조각은 출력·저장하지 않습니다.

이 도구는 NAS 운영자가 직접 검증하는 용도입니다. 모아 로그인 세션이나 개인 원장에 연결하지 않으며 공동관리자의 자료도 저장하지 않습니다. 향후 개인별 연결 화면·저장·예약 작업은 별도로 구현합니다.

## 5. Mac으로 이전한 경우

Mac의 기존 Git 방식으로 최신 코드를 받은 뒤 [Mac Compose 설정](MAC.md)을 함께 적용해 앱을 재빌드합니다. 비밀 파일은 NAS의 호스트 폴더 대신 **`moa_mac-secrets` 볼륨**에 넣습니다.

```sh
cd moa/deploy
docker compose -f compose.nas.yml -f compose.mac.yml --profile mail up -d --build app mail-poller
docker compose -f compose.nas.yml -f compose.mac.yml run --rm --no-deps \
  --user 0 \
  -v moa_mac-secrets:/setup-secrets \
  app python scripts/configure-codef.py
```

## 정식(운영) 환경으로 바꾸기

기본은 CODEF **데모** 환경(`development.codef.io`)입니다. CODEF와 정식 계약을 맺고 운영 키를 받았다면 `deploy/.env`에 다음을 적고 app·codef-worker를 다시 시작합니다.

```sh
MOA_CODEF_ENV=production
```

`demo`와 `production` 두 값만 받으며, 주소를 직접 입력할 수는 없습니다(키·토큰이 다른 서버로 가지 않도록). 2단계 키 입력에는 운영 키를 넣습니다. 데모와 운영의 연결 ID는 서로 쓸 수 없으므로 환경을 바꾼 뒤 각 구성원이 카드·계좌를 다시 연결해야 합니다.

## 보관·권한·오류

서버 비밀 폴더의 `codef-app.json`에만 설정을 저장합니다. 폴더는 700, 파일은 600, 컨테이너 앱 사용자 UID/GID 1000 권한으로 준비합니다. 파일은 디스크에 평문으로 보관되므로 NAS 관리자/root는 읽을 수 있습니다. 앱에는 읽기 전용으로 마운트하고 Git·이미지 빌드·브라우저·로그에는 값을 넣지 않습니다. 기존 Gmail·명세서 암호 파일은 변경하지 않습니다.

설정이 없거나 잘못되면 버튼을 비활성화합니다. 인증 서버 오류는 원문 대신 안전한 분류 문구만 표시합니다. Client ID·Secret 오류는 데모버전 값을 확인하고, 네트워크 오류는 서버 인터넷·인증서 설정을 확인합니다. 인증 확인 DB에는 설정 비교용 해시·요청 시각·성공 여부·일반 안내만 저장하며 발급 토큰을 보관하지 않습니다. 키를 교체하면 예전 설정의 인증 성공 결과는 표시하지 않습니다.

이 단계는 개발자 설정이므로 소유자만 확인할 수 있습니다. 공동관리자에게 키를 공유하거나 같은 도구를 개인마다 실행할 필요는 없습니다. 향후 카드사 연결은 각자의 모아 계정에 분리해 구현합니다. API 키·카드사 암호·인증번호를 채팅으로 보내지 마세요.


## 저장 실패 원인 확인

최신 설정 도구는 입력 형식과 파일 쓰기 문제를 나눠 안내합니다. 제공된 RSA 공개키의 형식·종류를 검증하며 키 길이를 임의로 1024비트 이상으로 가정하지 않습니다. 로컬에서 공개키를 새로 만들거나 CODEF 공개키를 다른 키로 바꿀 필요는 없습니다.

- `client_id/client_secret ... 비어 있습니다/형식을 확인`: CODEF의 해당 항목 복사 버튼으로 **값만** 복사합니다.
- `public_key를 RSA 공개키로 읽지 못했습니다`: 공개키 복사 버튼으로 전체 값을 복사합니다. Client Secret을 이 항목에 넣지 않습니다.
- `비밀 폴더/파일 권한 설정 실패`: 명령의 `--user 0`과 NAS 폴더 권한을 확인합니다.
- `읽기 전용`: 설정 명령에 쓰기용 `/setup-secrets` 볼륨이 연결됐는지 확인합니다. 실행 중 앱의 `/run/moa-secrets:ro`는 그대로 유지합니다.
- `저장 공간이 부족`: NAS 저장소 여유를 확인합니다.

키를 입력하지 않고 쓰기 경로만 확인하려면 같은 NAS 폴더에서 다음을 실행합니다. 기존 키를 읽거나 변경하지 않고 실행 UID·폴더 존재·임시 파일 쓰기 결과만 표시합니다.

```sh
sudo docker compose -f compose.nas.yml run --rm --no-deps \
  --user 0 \
  -v "$PWD/secrets:/setup-secrets" \
  app python scripts/configure-codef.py --diagnose
```

Mac에서는 앞의 Mac 명령에서 같은 `--diagnose`를 사용합니다. 문의할 때는 오류 안내 문구만 전달하고 키 원문이나 키가 보이는 터미널 화면을 공유하지 않습니다.


## 계정 등록 없이 지출을 수동 저장하려면

위의 `verify-codef-card.py`는 건수만 확인합니다. 실제 지출 저장을 명시적으로 요청하려면 최신 코드·이미지와 [자동·수동 저장 안내](CODEF_AUTO.md)의 저장 키 준비 후 맥에서 다음을 실행합니다.

```sh
cd "$HOME/moa-projects/moa/deploy"
docker compose -f compose.nas.yml -f compose.mac.yml run --rm --no-deps \
  app python scripts/connect-codef-card.py --card lotte --user owner --direct
```

이 명령은 계정 등록 API를 거치지 않고 **최근 7일**을 승인 상품 API로 직접 조회합니다. `--user`는 본인 모아 아이디입니다. 연결 ID 없이 사용할 수 있으며, 지원하는 다른 카드사도 `--card` 이름을 바꾸면 됩니다. 명세서와 겹치는 후보·모호한 취소를 임의로 합산하지 않고 기존 개인 원장 검증·중복 방지·검토 규칙을 적용합니다. 저장된 지출은 ‘사용 내역’ 새로고침으로, 마지막 수동 조회 상태는 ‘계정 → 내 카드 자동 수집 · CODEF’에서 확인합니다.

로그인 정보·본인 확인 값·인증번호·세션은 저장하지 않으며 기존 자동 연결과 다른 카드사의 수집을 변경하지 않습니다. 이 명령은 **그때 한 번의 수동 조회·저장**이고 하루 4회 자동 수집을 시작하지 않습니다. 다시 조회하려면 매번 사용자가 실행해야 하며 기본 하루 60회 로컬 예산에 포함됩니다. 저장 기록 이름은 `CODEF 조회 · YYYY-MM`으로 표시합니다. `CF-04034`에 재개 정보가 없는 경우에는 이 경로도 진행할 수 없으며, 실제 운영 성공 여부는 실행 결과로 확인해야 합니다.
