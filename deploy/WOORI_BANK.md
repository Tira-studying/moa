# 우리은행 개인 입출금 연결

우리은행(`0020`)의 본인 원화 수시입출 계좌 한 곳씩 연결합니다. 토스뱅크·지역화폐·온누리는 이 기능에 포함하지 않습니다. 기존 카드 수집과 DB·비밀·Tailscale 볼륨을 그대로 사용합니다.

## 최초 연결

휴대폰에서는 **더보기 → 카드·계좌 연결 → 계좌 → 우리은행**을 선택합니다. 공동관리자도 본인 계정에 직접 연결할 수 있습니다. 입력·동의·추가 인증·취소·보관 범위는 [휴대폰 연결 안내](PHONE_CONNECTIONS.md)를 참고하세요. 아래 터미널 명령은 운영자용 대체 경로입니다.

새 코드로 앱과 CODEF 작업자를 빌드한 다음, 대화형 터미널에서 실행합니다. `owner` 대신 본인의 모아 아이디를 명시하세요.

```sh
docker compose -f compose.nas.yml -f compose.mac.yml exec app python scripts/connect-codef-bank.py --user owner
```

도구는 전송·암호화 저장 범위를 먼저 보여 주며, `연결`을 숨김 입력한 경우에만 진행합니다. 인터넷뱅킹 아이디·비밀번호, 생년월일 **8자리 YYYYMMDD**, 조회할 본인 계좌번호·계좌비밀번호 4자리를 터미널에만 입력합니다. 비밀번호·인증번호·계좌번호를 채팅·명령 인자·환경변수에 넣지 마세요. 카드 홈페이지 로그인과 은행 인터넷뱅킹 로그인은 별개입니다. 공동인증서가 필요한 계정이나 지원하지 않는 추가 인증은 중단하며 성공으로 표시하지 않습니다.

우리은행의 은행별 로그인 명세는 `withdrawAccountNo`·`withdrawAccountPassword`를 아이디 로그인 필수값으로 지정합니다. 같은 조회 계좌와 RSA 암호화 계좌비밀번호를 등록 요청부터 전달하고, 최초 조회·작업자의 연결 ID 조회에도 동일한 확인값을 사용합니다. 이 항목은 은행 로그인 확인용이며 이체 요청을 하지 않습니다. 생년월일은 명세의 YYYYMMDD를 따르며 6자리 입력을 추정해 늘리지 않습니다.

입력과 형식 검증을 모두 마친 뒤 계정 등록 → 연결 ID로 해당 계좌 조회 순서로 각 한 번만 요청합니다. `CF-04000`은 전체 계정 등록 실패 코드이며, 단일 우리은행 응답에 세부 오류가 있으면 **기관 상세 코드**와 알려진 누락 키만 표시합니다. CF-12401/CF-12411의 문서상 `reqUserPass` 기호는 `password`로 표시하고, 알 수 없는 userError·입력값·응답 원문은 진단 기록에 남기지 않습니다. 홈페이지에서 아이디 로그인을 확인하고 입력을 바로잡기 전에는 반복 실행하지 마세요.

도구는 비밀 입력 전에 토큰 발급·등록·최초 조회에 필요한 로컬 예산이 최소 3회 남았는지 확인합니다. 부족하면 입력·토큰 발급·등록을 시작하지 않습니다. 통신 오류의 선택 재요청도 예산이 최소 1회 남아야 표시합니다. 실제 호출 직전에도 기존 공용 장부를 다시 검사하므로 동시 작업이나 추가 인증으로 예산이 소진되면 중단할 수 있습니다. 로컬 예산이 소진됐다고 공급자 한도가 모두 사용된 것은 아니며, 장부를 지우거나 실제 무료/계약 범위 확인 없이 상한을 늘리지 마세요.

로그인 비밀번호와 계좌비밀번호는 CODEF 공개키로 RSA 암호화해 TLS로 전송합니다. CODEF 계정 등록은 로그인 정보를 CODEF에 보관하는 연결 ID를 만듭니다. 로컬에는 연결 ID·계좌번호·생년월일·RSA 암호화 계좌비밀번호만 기존 별도 비밀 키로 Fernet 암호화해 DB에 저장합니다. 평문 비밀번호·OTP·응답 원문·예금주·전체 계좌번호 표시는 보관하지 않습니다. 금융기관의 비밀번호 오류 제한(우리은행 3회)을 피하기 위해 실패를 자동 재시도하지 않습니다. 계좌 비밀번호가 확실하지 않으면 취소하세요.

기관별 단일 등록 성공과 해당 계좌의 최근 30일 조회를 모두 검증한 후에만 새 연결과 입출금을 한 트랜잭션으로 저장합니다. 실패·사용자 해제·동시 교체 시 기존 연결과 내역을 보존합니다. 공급자 쪽에서 등록만 성공한 뒤 조회가 실패할 수 있으며, 이 경우 로컬 자동 수집 연결은 만들어지지 않습니다.

`CF-12200`은 [CODEF 공식 오류표](https://developer.codef.io/common-guide/error-code)의 통신 연결 실패 코드입니다. 로그인 등록 후 입출금 조회에서 이 코드가 오면 도구는 입력을 다시 받지 않고 선택을 기다립니다. 우리은행 홈페이지 접속 상태를 확인한 뒤 `1`을 선택하면 메모리의 동일 연결·계좌 확인값으로 **조회만 한 번 더** 전송합니다. Enter나 다른 값은 종료하며, 두 번째 오류나 로그인/계좌 인증 오류는 다시 요청하지 않습니다. 등록 자체가 실패한 경우에는 이 선택 재요청을 적용하지 않습니다. 자동 수집 작업자는 이 코드(와 CF-12701)를 받으면 그 회차만 건너뛰고 다음 회차(6시간 뒤)에 한 번 다시 조회하며, 두 번 연속 실패하면 멈춥니다. 종료하면 보관되지 않은 입력은 다시 사용할 수 없습니다.

`CF-12701`은 같은 공식 오류표의 전문·페이지 변경 응답입니다. 비밀번호 재입력이 필요한 오류로 단정하지 않고 연결 확인 오류로 표시하며 자동 수집을 멈춥니다. 저장한 연결·입출금은 보존합니다. 운영자가 한 번 재검증한 뒤에도 반복되면 요청 식별자와 시각으로 CODEF에 확인해야 합니다.

## 사용

모아 **더보기 → 계좌 입출금**에서 본인 내역을 확인합니다. 날짜·입금·출금·거래 후 잔액·거래 설명을 표시하며, 월마다 최신 1,000건까지 표시합니다. **화면 새로고침**은 외부 금융 요청을 보내지 않습니다. **자동 수집 연결·상태**를 펼치면 연결 상태·수동 요청·중지 버튼이 나옵니다. **지금 수집**은 수집 가능한 본인 연결에만 요청하며, **수집 중지**는 기존 내역을 보존합니다. 중지 해제·인증 교체는 위 터미널 도구로 다시 검증합니다.

기존 단일 CODEF 작업자가 한국시간 00·08·14·20시에 최근 30일을 조회합니다. 최초 연결 시점보다 오래된 내역의 일괄 수집은 포함하지 않습니다. OAuth·등록·추가 인증·입출금 조회는 카드와 같은 하루 로컬 요청 예산을 사용합니다. 이체·결제 API는 사용하지 않습니다.

은행 출금에는 계좌이체·카드 대금·지갑 충전·체크카드 결제가 섞일 수 있으므로 **자동 합산하지 않습니다**. 입금도 자동으로 소득이라고 분류하지 않습니다. 계좌 입출금 상세와 확인 기록은 공동관리자에게 공유하지 않습니다. 아래 절차로 직접 확인한 실제 지출만 개인 원장과 통합 합계에 반영합니다.

## 출금을 실제 소비와 구분하기

1. **더보기 → 계좌 입출금**에서 소비로 합산할 출금의 **소비로 선택**만 체크합니다. 카드 대금·내 계좌 이체·충전 등은 선택하지 않으면 됩니다. 미선택 내역에는 정리 알림을 띄우지 않습니다.
2. 체크하면 사용 내역에 반영하고, 해제하면 합계에서 뺍니다. 카드 후보가 없으면 추가 입력이 필요 없습니다. 입금·금액 변동 없는 기록은 선택할 수 없습니다.
3. 같은 금액·앞뒤 3일의 카드 사용 내역이 있으면, 카드 후보와 별개인 지출임을 확인해야 반영합니다. 같은 거래라면 닫고 선택하지 않은 상태로 둡니다. 날짜·금액만으로 동일 거래를 확정하지 않습니다.
4. 사용처·소비 분야·메모는 **분류·상세**에서 수정할 수 있습니다. 새 선택은 미분류·분야 확인 전 상태이며, 이후 사용 내역에서 분류해도 됩니다. 선택 해제·재선택은 기존 분류·메모·분야 확인 상태를 보존합니다. 상세 폼에서 카드 대금·이체·충전·카드 중복을 별도로 기록하는 기능도 유지합니다.
5. 나중에 새 카드 중복 후보가 들어오면 선택한 **계좌 소비만 보류**합니다. 선택 체크는 유지하되 합계에서는 빠지고 **중복 확인 필요**로 표시합니다. 카드 저장과 보류는 같은 트랜잭션으로 처리합니다. 별개 지출이면 재확인하고, 같은 거래면 체크를 해제합니다. 대시보드 알림은 이 보류 건에만 표시합니다.

확인한 소비는 사용 내역에 **우리은행 계좌**로 표시하고 사용 카드 개수·카드 청구·납부 목록에는 넣지 않습니다. 취소할 때는 원장을 지우지 않고 집계만 제외해 분류·메모와 연결을 보존합니다. 다시 확인해도 같은 출금을 중복 추가하지 않습니다. 저장 기록에서 계좌 지출 묶음을 직접 삭제한 경우에는 자동 복원하지 않으며, 필요한 경우 계좌 화면에서 다시 확인합니다.

후보 확인과 정리 저장은 이미 보관한 자료만 사용하므로 CODEF 요청을 추가하지 않습니다. 공동관리자 활성 여부와 관계없이 최신 개인 버전을 검사하며, 편집 중 다른 화면이나 자동 수집이 바꾸면 저장을 거절하고 최신 후보를 다시 불러오도록 합니다. 계좌 사용처·메모는 함께 열람의 고정 지출·중복 목록에도 보내지 않고, 확인한 소비의 총액·분야·결제 수단 합계만 통합에 반영합니다.

거래 식별자는 계좌·일시·입출금·잔액의 HMAC이며 같은 조회는 중복 저장하지 않습니다. 같은 시각·금액·잔액이 반복되는 건은 발생 순번으로 구분합니다. 설명 변경은 갱신하며, 은행이 날짜·금액·잔액을 사후 정정한 내역의 자동 대조·삭제는 지원하지 않습니다. 잘못된 날짜·금액·다른 계좌·알 수 없는 응답은 목록 전체를 저장하지 않고 멈춥니다.

입금액과 출금액이 모두 0원인 기록도 삭제하거나 출금으로 해석하지 않고 보존하며, 화면에는 **금액 변동 없음**으로 표시합니다. 음수 입출금이나 입금·출금이 동시에 양수인 기록은 전체 응답 검증에서 계속 차단합니다.

공식 명세: [수시입출 거래내역](https://developer.codef.io/products/bank/common/p/transaction), [은행 개요](https://developer.codef.io/products/bank/overview), [계정 등록](https://developer.codef.io/common-guide/connected-id/register). 은행별 상세 인증표의 접근 여부와 실제 계정 인증 결과는 구분해야 하며, 문서상 지원을 운영 연결 성공으로 간주하지 않습니다.
