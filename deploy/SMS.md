# 아이폰 결제 문자를 모아로 보내기

아이폰 단축어의 메시지 자동화가 선택한 카드사 문자를 HTTPS로 전달합니다. 모아가 문자함을 조회하거나 카드사 앱 알림을 읽지는 않습니다. **현재 지원 양식은 KB국민·신한·삼성·현대카드 국내 원화 승인·취소 문자**입니다. 그 외 카드사·해외 결제·거절 알림은 추측해서 저장하지 않고 오류로 반환합니다.

문자 수신만 설정해서는 모아에 반영되지 않습니다. 서버를 업데이트하고 아래 자동화를 연결해야 합니다. 실제 아이폰의 잠금 상태·네트워크·iOS 버전에 따른 자동 실행은 해당 기기에서 확인해야 합니다.

## 1. 서버 업데이트

현재 사용 중인 개인 원장 버전에서 이 업데이트는 문자 표와 현대 상품명 열을 준비하며 기존 거래는 변경하지 않습니다. 상품명 열이 없던 버전에서는 시작할 때 자동으로 추가하며 기존 수신 키·문자 내역·중복 판정 값은 유지합니다. 기존 운영 백업을 유지하세요. 개인 원장 분리를 아직 적용하지 않은 구버전이라면 먼저 [개인 관리 안내](../docs/PERSONAL_SHARING.md)의 이전 절차를 따릅니다.

Git이 없는 NAS의 기존 설치 구성에서는 다음을 실행합니다. 원래 Git SSH 키 볼륨 이름이 다른 경우 기존 이름을 사용하세요.

```sh
cd "$HOME/moa-projects"
sudo docker run --rm -it \
  -v "$PWD":/git -w /git/moa \
  -v moa-git-ssh:/root/.ssh \
  alpine/git pull --ff-only origin main
cd moa/deploy
sudo docker compose -f compose.nas.yml --profile mail up -d --build app mail-poller
```

Mac으로 이전했다면 [Mac 이전 안내](MAC.md)에 따라 같은 코드를 받고 Mac용 Compose 설정을 함께 적용합니다. 새 외부 포트를 열거나 Tailscale Funnel을 켤 필요는 없습니다.

## 2. 모아에서 본인 수신 키 발급

1. 아이폰에서 Tailscale을 켜고 모아에 **본인 계정**으로 로그인합니다.
2. 로그인한 모아 주소 뒤에 `/#sms`를 붙여 **실시간 소비 · 문자 → 아이폰 단축어 연결 · 수신 키 관리**를 엽니다. 대시보드 문자 요약과 메뉴는 기본 화면에서 숨겨 두었으며 기존 수신·조회 기능은 유지합니다.
3. **새 키 발급 · 기존 키 교체**를 누릅니다.
4. 전송 주소와 수신 키를 아래 단축어에 입력합니다. 키는 이번에만 보이고 화면 이동·백그라운드 전환·90초 경과 시 표시를 지웁니다. 다시 필요하면 새 키를 발급하고 단축어도 교체합니다.

운영 주소가 현재 설정과 같다면 수신 주소는 다음과 같습니다. 화면에 표시된 주소를 우선하세요.

```text
https://moa-card.YOUR-TAILNET.ts.net/api/sms/receive
```

키는 43자의 임의 문자열입니다. 비밀번호·카드 번호·명세서 암호를 넣는 곳이 아닙니다. 모아는 키의 해시만 저장합니다. 키는 본인 임시내역을 추가할 수 있지만 조회·수정·공동 계정 관리 권한은 없습니다. 키를 URL이나 요청 본문에 넣지 말고 아래 Authorization 헤더에만 사용하세요.

공동관리자는 자신의 계정에서 따로 키를 발급합니다. 상대방 키를 함께 쓰면 상대방 개인 내역으로 들어갑니다. 키 교체·해제 또는 계정 해제·앱에서 암호 변경 시 이전 키를 사용할 수 없습니다.

## 3. 우선 전송용 단축어 만들기

iOS 버전에 따라 동작 이름이나 변수 선택 화면의 문구가 조금 다를 수 있습니다.

1. **단축어 → 단축어 탭 → ＋**에서 새 단축어를 만들고 이름을 `모아 문자 전송`으로 지정합니다.
2. **URL 콘텐츠 가져오기** 동작을 추가하고 위 수신 주소를 입력합니다.
3. 동작의 세부 옵션을 펼쳐 **방법을 POST**로 지정합니다.
4. 헤더를 다음처럼 추가합니다.

| 헤더 이름 | 값 |
| --- | --- |
| `Authorization` | `Bearer 여기에_본인_수신_키` |
| `X-Requested-With` | `CardDashboard` |
| `Content-Type` | `application/json` |

`Bearer` 다음은 **공백 한 칸**이며 키 앞뒤에 따옴표를 넣지 않습니다. 키를 입력한 화면·단축어 파일을 다른 사람과 공유하지 마세요.

5. **요청 본문은 JSON**을 선택합니다.
6. 키가 `text`이고 유형이 **텍스트**인 항목 하나를 만듭니다. 값에는 **단축어 입력의 메시지 본문 텍스트**를 넣습니다. 입력 변수 선택에서 본문·콘텐츠 등의 속성이 보이면 메시지 전체 객체 대신 실제 본문을 선택합니다. 필요하면 앞에 **입력에서 텍스트 가져오기** 동작을 추가하고 그 결과를 연결합니다.
7. 확인용으로 마지막에 **결과 보기** 동작을 잠시 추가합니다. 연결 검증 후 삭제하면 팝업 없이 사용하기 편합니다.

요청 형식은 다음과 같습니다. JSON 코드를 직접 타이핑하기보다는 단축어의 JSON 입력칸과 변수 선택을 사용하세요.

```json
{"text": "단축어가 받은 메시지 본문"}
```

이 단축어에는 모아 로그인 쿠키·비밀번호나 별도의 `owner_id`가 필요 없습니다. 서버는 키에 연결된 계정으로만 저장합니다.

## 4. 실제 문자 전 자동화 없이 시험하기

새 전송용 단축어 앞에 **텍스트** 동작을 임시로 추가합니다. 아래는 가상 예시이며, 날짜와 시각은 **지금 한국 날짜·시각**으로 바꾸세요. 요청 본문의 `text` 값도 시험 동안 이 텍스트 동작의 결과로 연결합니다.

```text
[Web발신]
KB국민카드2222승인
가*상님
12,500원 일시불
MM/DD HH:mm
가상상점
누적98,000원
```

재생 버튼을 누르고 네트워크 요청 허용 안내가 나오면 모아 주소로의 요청을 허용합니다.

- `{"ok":true,"duplicate":false}`: 새 임시내역을 받았습니다. HTTP 상태는 201입니다.
- `{"ok":true,"duplicate":true}`: 같은 내용·시각의 알림을 이미 받았습니다. 추가 저장하지 않습니다.
- 오류에 `문자 수신 키`가 나오면 Authorization의 공백·키·교체 여부를 확인합니다.
- `앱 화면에서 다시 요청`은 `X-Requested-With` 헤더를 확인합니다.
- 양식 오류는 JSON의 `text`에 메시지 **본문**이 전달됐는지 확인합니다.
- 연결 실패는 Tailscale·인터넷·서버 상태를 확인합니다. 실패한 전송이 자동 보관·재전송되지는 않습니다.

모아 **실시간 소비 · 문자 → 새로고침**에서 가상 결제가 보이는지 확인합니다. 시험 내역은 **제외**합니다. 이어 같은 가상 내용에서 `승인`을 `취소`로 바꾸면 취소가 음수로 들어오는 것도 확인할 수 있습니다. 시험 뒤 임시 텍스트 동작을 삭제하고 JSON 값을 다시 **단축어 입력**으로 바꿉니다.

## 5. 카드사 메시지 자동화 연결

1. **단축어 → 자동화 → ＋ → 메시지**를 선택합니다.
2. **발신자**는 실제 해당 카드사의 결제 문자를 받은 번호를 지정합니다. 전체 문자에 적용하지 마세요.
3. **메시지 포함** 조건은 아래 표에 맞춰 지정합니다. `승인`만 조건으로 걸면 취소 문자는 빠집니다.
4. 지원되는 iOS에서는 **즉시 실행**을 선택합니다. 확인 후 실행만 가능하면 자동 전송에 매번 확인이 필요할 수 있습니다.
5. 실행할 동작으로 **단축어 실행 → 모아 문자 전송**을 추가합니다.
6. 해당 동작의 **입력**에는 자동화가 받은 **메시지 본문**을 연결합니다. 전송 단축어를 입력 없이 실행하면 본문이 비어 오류가 납니다.
7. 새 결제 문자가 왔을 때 전송되고 모아에 표시되는지 확인합니다. 실제 자동 수신은 이 단계에서 기기별로 검증됩니다. iOS의 권한 안내·잠금 상태·절전·네트워크 환경 때문에 즉시 실행을 항상 보장할 수는 없습니다.

카드사별로 자동화를 하나씩 만들되, **같은 `모아 문자 전송` 단축어와 본인 수신 키**를 사용하면 됩니다. 이번 카드사 지원 업데이트를 위해 기존 키를 다시 발급할 필요는 없습니다.

| 카드사 | 메시지 포함 조건 | 지원 본문 |
| --- | --- | --- |
| KB국민 | `KB국민카드` | 카드 끝자리·승인/취소·금액·날짜·가맹점이 여러 줄로 구분된 양식 |
| 신한 | `신한카드(` | 끝자리 괄호·승인/취소·금액(결제 방식)·날짜·가맹점·누적액이 한 줄인 양식 |
| 삼성 | `삼성` | 첫 줄에 끝자리·승인/취소·이름, 다음 줄에 금액, 다음 줄에 날짜·가맹점, 마지막 줄에 누적액인 양식 |
| 현대 | `현대` | 상품명·승인/취소, 이름, 금액, 날짜·시각, 가맹점, 누적액이 여섯 줄인 양식 |

신한·삼성·현대의 누적액은 저장하지 않습니다. 삼성 취소의 `-`는 원래 승인액을 두 번 빼거나 양수로 바꾸지 않고 취소액에 한 번만 적용합니다. 취소액이 양수로 표기된 같은 문자를 다시 보내도 같은 취소 건으로 판단합니다. 현대카드의 첫 줄에 있는 상품명은 별도로 표시하고, 원문에 없는 카드 끝자리는 추측하지 않아 ‘번호 미표시’로 표시합니다. RCS에서 접힌 미리보기 대신 전체 본문이 단축어로 전달되어야 합니다. 일부 본문이나 링크만 전달되면 저장하지 않습니다.

아이폰 Tailscale은 수신 주소에 접속할 수 있는 계정으로 켜 두어야 합니다. 모아 페이지를 계속 열어 둘 필요는 없지만 서버는 실행 중이어야 합니다. 단축어·iOS가 전송하지 않은 문자는 모아에서 복구할 수 없으므로 월말 명세서와 반드시 대조합니다.

## 6. 임시내역의 의미와 대조

- 문자 화면은 화면이 보일 때 15초 간격으로 조회합니다. 수동 새로고침도 가능합니다.
- 본문 원문·이름·누적액은 저장하지 않고 카드사·끝 4자리·승인/취소·결제액·가맹점·이용 시각·일시불/할부 표시만 저장합니다. 끝 4자리는 개인 화면에서 카드 구분용으로만 사용합니다. 현대처럼 끝자리가 없는 문자는 빈 값으로 두고 상품명만 따로 저장합니다.
- 원문에 연도가 없어 **한국 수신 시각과 가장 가까운 연도**를 적용합니다. 최근 7일 이내이며 최대 5분의 시계 차이만 허용합니다. 연말·연초를 처리하지만 늦게 도착한 과거 문자는 명세서로 등록해야 합니다.
- 제외하지 않은 전체 문자의 승인 합계·취소 합계·문자 기준 순사용액을 표시합니다. 명세서 대조 완료한 문자도 합계와 기본 목록에 남습니다. 취소는 원래 승인과 날짜·월이 다를 수 있고 할부 승인액은 전체 원금이므로 **월별 납부액이 아닙니다**.
- 동일 계정의 카드사·끝 4자리·승인/취소·금액·이용 분·가맹점·결제 방식이 같으면 재전송으로 처리합니다. 현대는 상품명도 함께 비교하지만 같은 상품의 서로 다른 실제 카드를 구분할 수는 없습니다. 같은 분에 동일한 정상 결제를 두 번 했다면 구분할 수 없어 명세서 확인이 필요합니다. 승인과 취소는 별개입니다.
- 명세서에서 카드사·이용일·정리한 가맹점·부호 포함 금액이 같은 개인 거래가 있으면 **대조 후보**로 표시합니다. 원장에는 카드 끝자리가 없고 상호 표기도 다를 수 있어 자동 결합하지 않습니다. 본인 원본을 확인하고 **명세서와 대조 완료**를 누르세요. 대조 완료는 비교 상태만 표시하며 문자 기준 합계와 목록을 유지합니다. ‘문자 집계에서 제외’를 선택한 내역만 합계에서 빠집니다.
- 잘못 전달한 시험 내역은 **제외**할 수 있고, 제외 내역도 보기를 켜면 **미대조로 복원**할 수 있습니다. 대조 완료 내역은 기본 목록에서 항상 확인하고 미대조로 바꿀 수도 있습니다. 원래 명세서 거래는 바뀌지 않습니다.
- 명세서 원장·기존 소비 분석·통합 지출·청구·납부 상태에는 문자액을 더하지 않습니다. 양쪽 합계를 더하면 중복될 수 있습니다. 문자 소비 화면에서 별도로 제공하며 대시보드 요약은 숨겨 두었습니다.
- 문자 발신자는 금융기관 인증 증거가 아닙니다. 임시 소비 참고 자료로 사용하고, 잘못된 알림·취소·빠진 전송은 실제 카드 명세서로 확인하세요.

## 개발 흐름

`sms_inbox.py`가 카드사별 엄격한 양식 해석, 쓰기 전용 수신 키, 임시내역·대조 후보를 담당합니다. `static/sms.js`는 키 일회 표시, 목록 갱신, 개인 대조 상태를 담당합니다. 키 관리와 대조 수정은 기존 로그인·개인 버전·변경 이력 검사를 통과해야 합니다. 수신 API만 세션 대신 전용 Bearer 키를 사용하며 HTTPS 호스트·Origin·요청 헤더 검사를 유지합니다. DB 쓰기 잠금 안에서 활성 사용자와 키를 재확인하고 분당 120회 제한·8KiB 요청 제한·문자 2,000자 제한을 적용합니다.

원문·키를 앱 로그·변경 이력·브라우저 저장소에 복제하지 마세요. 기본 테스트는 `test_sms_inbox.py`, 실제 서버·모바일 화면 검증은 `MOA_BROWSER_TESTS=1`로 같은 파일을 실행합니다. 테스트는 가상 자료와 임시 DB만 사용합니다.


## 문자 형식 오류가 표시될 때

JSON의 왼쪽 키는 `text`, 오른쪽 값은 설명 문구가 아닌 실제 승인 또는 취소 한 건의 본문이어야 합니다. 주소·인증을 통과한 뒤 양식 오류가 나오면 키를 다시 발급하기보다 본문부터 확인하세요. 금액·일시·가맹점과 마지막 누적액이 빠지거나 서로 다른 문자를 합치면 저장하지 않습니다.

단축어 입력칸에서 줄바꿈이 공백으로 바뀌거나 `[Web발신]`이 카드사 이름과 같은 줄에 붙는 경우도 최신 서버에서 지원합니다. 원래 줄 구성도 계속 지원하며 같은 내용은 재전송으로 처리합니다. 공백 형식은 누적액을 마지막 구분자로 요구하되 해당 금액은 저장·합산하지 않습니다. 기존 수신 키·단축어 설정은 유지하고 서버 업데이트 후 같은 본문으로 다시 실행할 수 있습니다.


## 대조 완료한 지출을 다시 확인하기

로그인한 모아 주소 뒤에 `/#sms`를 붙여 **실시간 소비 · 문자**를 열고 이용 월을 선택하세요. 이전 버전에서 완료 처리한 내역도 최신 화면에서는 자동으로 표시됩니다. 문자는 수신 시 보관되며 ‘명세서와 대조 완료’는 저장 버튼이 아니라 명세서와 비교했음을 표시하는 상태 변경입니다. 완료 처리해도 지출과 문자 기준 합계는 유지됩니다. 제외한 건만 목록·합계에서 빠지고 ‘제외 내역도 보기’로 확인·복원할 수 있습니다.

대시보드의 문자 요약과 관련 자동 조회는 숨김 상태에서 중단합니다. 문자 상세 화면은 직접 열었을 때 15초마다 갱신합니다. 선택 월별 상세는 실시간 소비 화면에서 확인합니다. 문자 소비와 명세서 소비는 서로 겹칠 수 있어 별도 합계로 표시하며 두 금액을 더하지 않습니다. 일반 사용 내역·통합 지출·월별 청구액에는 문자 금액을 자동으로 추가하지 않습니다.
