# Gmail 명세서 자동 수집

NAS가 Gmail의 `MOA` 라벨을 읽어 첨부파일을 분류합니다. 약 5분 간격으로 한 번에 신규 메일 10개씩 확인하며, 처음에는 라벨의 기존 메일부터 순서대로 수집합니다. 브라우저의 목록 새로고침은 이미 수집한 목록을 갱신합니다. 메일은 읽음 처리하거나 삭제하지 않습니다. 원본 메일/첨부는 Gmail에 남기고 NAS DB에는 파일명·추정 카드사·메일 식별자·검토 상태만 기록합니다. 같은 첨부가 여러 메일에 있으면 목록에는 각각 나타나지만 거래 저장 시 기존 파일 해시 중복 검사를 적용합니다.

## 0. 코드 업데이트

```bash
cd "$HOME/moa-projects"
sudo docker run --rm -it \
  -v "$PWD":/git -w /git/moa \
  -v moa-git-ssh:/root/.ssh \
  alpine/git pull --ff-only origin main
cd moa/deploy
```

## 1. Gmail 준비

1. 아이폰 또는 PC 브라우저에서 명세서를 모을 Gmail 계정에 로그인합니다. 전용 수집 계정을 사용하는 편이 관리하기 쉽습니다.
2. Google 계정 보안 설정에서 2단계 인증을 설정합니다.
3. https://myaccount.google.com/apppasswords 에서 앱 비밀번호를 만듭니다. 이름은 `모아 NAS` 등으로 정합니다. 일반 Google 로그인 비밀번호와 다릅니다. 계정 정책에 따라 앱 비밀번호 메뉴를 쓸 수 없으면 현재 방식 대신 OAuth 연결이 필요합니다.
4. Gmail 웹 설정에서 `MOA` 라벨을 만들고 가능하면 IMAP에 표시합니다. Gmail의 라벨/필터 설정은 데스크톱 웹사이트 보기나 PC에서 작업하는 것이 편합니다.
5. 카드사 명세서 메일에 `MOA` 라벨을 붙입니다. 앞으로 오는 메일에도 자동으로 붙도록 Gmail 필터를 만드세요. 처음에는 최근 명세서 몇 통으로 확인하세요. 대용량 첨부의 다운로드 링크나 본문 링크는 수집하지 않고 실제 첨부파일만 처리합니다.

앱 비밀번호 자체는 라벨 전용 권한이 아닙니다. 모아 프로그램이 읽기 전용으로 MOA 라벨만 선택합니다. Google 계정에서 언제든 앱 비밀번호를 폐기할 수 있습니다. Gmail 앱 비밀번호·명세서 비밀번호를 채팅이나 GitHub에 올리지 마세요.

## 2. NAS에서 비밀 파일 설정

SSH로 접속해 아래를 실행합니다. Docker 앱은 UID 1000으로 실행하므로 비밀 폴더와 파일도 해당 UID만 읽도록 만듭니다. 아래 두 비밀번호는 서로 다른 파일입니다.

```bash
cd "$HOME/moa-projects/moa/deploy"
sudo -v
sudo install -d -m 700 -o 1000 -g 1000 secrets
read -r -s -p "Gmail 앱 비밀번호: " MOA_MAIL_APP_SECRET
printf '%s' "$MOA_MAIL_APP_SECRET" | sudo tee secrets/gmail-app-password >/dev/null
unset MOA_MAIL_APP_SECRET
sudo chown 1000:1000 secrets/gmail-app-password
sudo chmod 600 secrets/gmail-app-password
```

공통 명세서 암호를 저장하려면 이어서 실행합니다. 입력 내용은 터미널에 표시되지 않습니다. 이 파일을 만들지 않으면 기존처럼 검토 때 직접 입력합니다.

```bash
read -r -s -p "공통 명세서 비밀번호: " MOA_STATEMENT_SECRET
printf '%s' "$MOA_STATEMENT_SECRET" | sudo tee secrets/statement-password >/dev/null
unset MOA_STATEMENT_SECRET
sudo chown 1000:1000 secrets/statement-password
sudo chmod 600 secrets/statement-password
```

비밀 파일은 NAS 디스크에 평문으로 보관됩니다. NAS 관리자/root는 읽을 수 있으며 파일 권한·디스크 암호화·백업 접근을 관리해야 합니다. 웹 화면에서 암호를 조회하는 API는 없고 이미지·Git·로그·브라우저로 전달하지 않습니다. NAS에서 위 명령을 다시 실행해 암호를 바꿀 수 있습니다. `secrets` 폴더는 Git과 이미지 빌드에서 제외됩니다.

## 3. 환경 설정

기존 `deploy/.env`의 `MOA_PUBLIC_ORIGIN`을 유지하고 아래 설정을 추가합니다. 이메일 주소를 실제 수집 계정으로 바꾸세요. 같은 설정은 한 번만 추가합니다.

```dotenv
MOA_GMAIL_USER=your-account@gmail.com
MOA_GMAIL_FOLDER=MOA
MOA_MAIL_SAMSUNG_ONLINE=0
```

삼성 파일이 공식 사이트로 폼을 전송하는 방식이면 `MOA_MAIL_SAMSUNG_ONLINE=1`로 변경합니다. 명세서의 열람 정보가 삼성 공식 HTTPS 사이트로 전송되는 것을 허용하는 설정이며, 자동 열기와 메일 검토 양쪽에 적용됩니다. 그 외 카드사의 외부 연결은 허용하지 않습니다.

## 4. 시작

```bash
sudo docker compose -f compose.nas.yml --profile mail up -d --build app mail-poller
sudo docker compose -f compose.nas.yml logs --tail 20 mail-poller
```

`Gmail poll completed`가 나오면 모아 웹 화면의 `이메일로 받은 명세서`에서 목록을 새로고침합니다. `failed`면 웹 화면의 연결 상태를 확인합니다. 실제 Google 계정 연결은 사용자 NAS 설정 후 확인해야 하며 가상 IMAP 서버로만 테스트했습니다.

모바일에서 카드사를 확인하고 두 자리 날짜의 적용 연도를 입력한 뒤 `검토 시작`을 누릅니다. 공통 암호가 있으면 자동으로 거래 후보 미리보기를 만들고, 없으면 파일 업로드 칸으로 이동해 암호를 입력합니다. XLSX/CSV는 기존 미리보기·제목 자동 찾기·마지막 거래 행 설정을 이용합니다. 거래 저장은 사용자가 날짜·가맹점·금액을 확인한 뒤 수행합니다.

## 자동 열기의 범위

공통 암호가 설정된 새 메일의 삼성·현대·롯데·우리 HTML 및 신한 PDF를 지원합니다. 자동 열기는 공식 발신 도메인과 Gmail이 기록한 첫 Authentication-Results의 DMARC 통과/발신 도메인 정렬 조건을 확인할 때만 시도합니다. 전달 메일이나 발신 인증을 확인할 수 없는 메일은 보류되며 사용자가 검토 시작에서 확인할 수 있습니다. 카드사 추정은 진위 보증이 아니므로 목록에서 확인하세요.

백그라운드 검사는 성공 여부와 후보 행 수만 남기고 추출 표는 버립니다. 검토를 시작할 때 다시 생성한 표는 기존과 같이 서버 메모리에 최대 10분 보관합니다. 거래 DB에 자동 저장하지 않습니다. 공통 암호 설정 전에 수집된 파일도 검토 시작 시 저장된 암호를 이용할 수 있습니다. 실패한 자동 검사는 무한 재시도하지 않으며 암호를 바꾼 후 검토 시작에서 다시 확인합니다.

메일 최대 16MB, 첨부 하나 최대 8MB입니다. HTML/PDF 파일별 기존 시간·크기·페이지 제한을 적용합니다. 지원하지 않는 카드사의 보안 파일, 암호화 XLSX, 이미지 PDF OCR은 별도 지원이 필요합니다. 원본이 Gmail에서 삭제되거나 UIDVALIDITY가 바뀌면 예전 참조를 읽지 않으며 새 목록을 확인해야 합니다.

## 중지/철회

```bash
sudo docker compose -f compose.nas.yml --profile mail stop mail-poller
```

Google 계정에서 앱 비밀번호를 폐기하면 Gmail 접속이 차단됩니다. 공통 암호 파일을 삭제하면 다음 검토부터 직접 입력합니다. Gmail 설정이 없어도 기존 모아 파일 업로드와 로그인은 사용할 수 있습니다. `docker compose down -v`는 사용하지 마세요.

### 명세서 처리 현황

모아의 ‘이메일로 받은 명세서’에서 첨부파일별 상태와 상태별 개수를 확인할 수 있습니다.

- **수신됨**: 수집된 첨부파일이며, 아직 내역을 읽었다고 확인하지 않은 상태입니다. ‘수집’ 시간은 Gmail 도착 시간이 아닌 모아가 발견한 시간입니다.
- **검토 필요**: 자동 열기를 보류했거나 내역 읽기에 실패했습니다. 파일별 안내를 확인하고 ‘검토 시작’을 누르세요.
- **열기 성공**: 거래 후보를 읽었습니다. 열과 거래 범위를 확인하고 직접 저장해야 지출에 반영됩니다.
- **저장됨**: 동일한 원본 파일에서 실제로 저장된 내역이 있습니다. 저장한 표 수와 거래 건수를 표시하며, 여러 표가 있는 명세서 전체의 저장 완료를 보장하지 않습니다.

저장 기록을 삭제하면 상태와 건수도 다시 계산합니다. 동일한 파일이 여러 메일에 첨부돼 있다면 각 첨부파일에 동일한 저장 결과를 표시합니다. 예전 버전에서 수집한 파일은 ‘검토 시작’을 한 번 눌러 원본을 확인한 후 저장 기록과 연결됩니다. 파일명 대신 원본 파일의 해시로 연결하며 원본은 보관하지 않습니다.

기본 목록은 ‘미저장 명세서’로, 저장된 파일은 숨깁니다. ‘저장됨’ 또는 ‘전체’ 필터로 다시 확인할 수 있습니다. 상태별 필터는 화면에 표시되는 최근 100개 첨부파일에 적용되고, 상단 개수는 수집된 전체 첨부파일 기준입니다. 화면을 보고 있는 동안 1분 간격으로 상태를 갱신하며, Gmail에서 새 메일을 수집하는 주기는 기존처럼 5분입니다. 업데이트 시 `app`과 `mail-poller`를 모두 다시 빌드하고 실행하세요.

### 일괄검토

파일별 ‘선택’ 체크박스 또는 ‘현재 목록 모두 선택’을 누르고 카드사를 확인한 뒤 ‘선택한 명세서 일괄검토’를 누르세요. CSV·XLSX는 제목 행과 거래 후보를 확인하고, 지원하는 보안 HTML·PDF는 NAS에 저장된 공통 비밀번호로 엽니다. 삼성카드의 외부 연결은 기존 `MOA_MAIL_SAMSUNG_ONLINE` 설정을 따릅니다.

파일을 한 번에 하나씩 처리하고, 실패한 파일이 있어도 다음 파일로 계속 진행합니다. 성공한 파일은 ‘열기 성공’ 상태로 바뀌고 선택이 해제되며, 실패한 파일은 결과에 사유를 표시하고 선택을 유지합니다. ‘중단’을 누르면 현재 파일 확인이 끝난 후 남은 작업을 멈춥니다. 화면을 닫으면 남은 작업을 자동으로 이어서 진행하지 않으므로 검토 중에는 페이지를 열어두세요.

일괄검토는 원본을 열어 거래 후보를 읽을 수 있는지 확인하는 기능입니다. 날짜·금액 열 선택과 원문 대조, 지출 저장은 각 파일의 ‘검토 시작’에서 진행합니다. 일괄검토 결과에는 원본·비밀번호·거래 표를 보관하지 않고 상태와 후보 행 수만 기록합니다. 저장된 명세서는 일괄검토 선택에서 제외합니다.


### 버튼으로 즉시 수집하기

‘목록 새로고침’은 기존 목록만 다시 읽는 대신 Gmail 수집을 즉시 요청합니다. NAS의 `mail-poller`가 요청을 확인하면 수집을 시작하고, 화면은 대기·수집 중·완료 상태와 새 파일을 자동 갱신합니다. 파일 열기와 Gmail 응답에는 시간이 걸릴 수 있습니다. 수집 요청은 NAS에 기록하므로 화면을 닫아도 작업은 계속됩니다.

자동 수집 주기는 5분으로 유지합니다. 수집기는 로컬 요청을 1초 간격으로 확인하며, 이 확인 자체로 Gmail에 접속하지는 않습니다. 중복 클릭은 진행 중인 요청 하나로 합치고, 한 수집기에서 순서대로 처리합니다. 수동 요청은 한 번에 최대 100통을 이어서 확인합니다. 남은 메일이 표시되면 다시 눌러 이어서 수집하세요. 메일은 기존과 같이 읽기 전용으로 확인하고 지출은 자동 저장하지 않습니다.

‘메일 수집기가 응답하지 않습니다’가 나오면 NAS에서 `mail-poller` 실행 상태를 확인하세요. 이 기능을 적용하려면 `app`과 `mail-poller`를 **둘 다 업데이트하여 재시작**해야 합니다. NAS에 기록된 대기 요청은 수집기가 시작되면 처리합니다.

## 개인 계정별 수집

이 문서의 기존 환경 변수와 비밀 파일은 소유자(1번)의 설정입니다. 공동관리자는 본인 Gmail·비밀 파일을 별도로 설정하며 소유자의 설정을 대신 읽지 않습니다. [개인 Gmail 설정 안내](../docs/PERSONAL_SHARING.md#4-개인-gmail-연결)에 NAS·Mac용 입력 도구와 디렉터리 구조를 정리했습니다.
