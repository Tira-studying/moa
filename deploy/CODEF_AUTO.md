# CODEF 자동 수집과 지출 저장 시작하기

최초 개인 연결과 재인증은 이제 [휴대폰 카드·계좌 연결](PHONE_CONNECTIONS.md)의 **더보기 → 카드·계좌 연결**에서 진행할 수 있습니다. 공동관리자도 본인 계정으로 로그인해 직접 인증하며 아래 운영자용 터미널 절차는 계속 사용할 수 있습니다. 현대 웹 연결은 별도 비밀 키로 이중 암호화한 `card_auth_cipher`를 DB에 보관하고 기존 비밀 파일·읽기 전용 마운트를 유지합니다.

`verify-codef-card.py`의 일회성 조회 시험은 연결 정보와 거래를 저장하지 않습니다. **수동으로 조회하고 지출을 저장**하려면 아래 `--direct` 방식을, **하루 4회 자동 수집**을 사용하려면 개인 연결 등록과 작업자 실행을 선택합니다. 이 안내는 이전을 마친 Apple Silicon Mac 기준입니다. NAS의 모아는 계속 중지 상태로 둡니다.

## 실제로 저장하는 것

- CODEF 계정 등록의 기관별 성공 결과와 연결 ID를 확인합니다. 연결 ID는 비밀 볼륨의 키로 암호화해 DB에 저장합니다.
- 기본 연결에서는 홈페이지 비밀번호·카드번호·PIN·본인 확인 값·인증번호·응답 원문을 영속 보관하지 않습니다. 아래의 **현대 암호화 추가 인증**을 명시적으로 설정한 경우만 카드번호와 CODEF용 PIN 암호문을 별도 비밀 볼륨에 Fernet 암호화해 보관합니다. PIN 평문은 보관하지 않습니다.
- 연결 ID만으로 승인 조회까지 확인한 카드는 `ready`가 됩니다. 검증 중에는 작업자가 조회하지 않습니다.
- 연결 ID를 사용하는 자동 수집은 최근 **30일**, `--direct` 수동 조회·저장은 최근 **7일**을 대상으로 합니다. 검증한 지출은 기존 개인 원장에 저장해 분야 분류·소비 분석에도 반영합니다. ‘사용 내역’ 새로고침 후 확인할 수 있습니다.
- 저장 기록의 묶음 이름은 `CODEF 조회 · YYYY-MM`입니다. 수동 저장도 포함하므로 이름만으로 자동 수집이 켜졌다고 판단하지 않습니다. 기존에 자동 생성한 CODEF 묶음의 이전 표시 이름만 갱신하고 일반 명세서 파일명은 바꾸지 않습니다.
- 원장에 저장된 자료에는 기존의 통합 합계 공유 정책이 적용됩니다. 상대방의 개별 거래·원본·연결 정보는 공유하지 않습니다.

현대의 카드번호·PIN 또는 롯데 등의 SMS 인증이 연결 ID 조회에서도 필요할 수 있습니다. 이 경우 `needs_auth`로 중단하고 자동 반복하지 않습니다. **6개 카드사의 직접 로그인 시험 성공이 6개 모두의 무인 조회를 보장하지는 않습니다.** 현대의 명시적 암호화 추가 인증은 아래 절차로 재사용 검증을 통과해야 사용할 수 있습니다. PIN 평문을 반복 보관하거나 브라우저 세션을 우회하지 않습니다.

## 1. 현재 맥 원장을 먼저 백업

NAS에서 가져온 백업은 이전 시점 자료입니다. 맥에서 변경한 자료를 보존하려면 현재 원장을 온라인 SQLite 백업으로 따로 복사합니다. DB 원문은 터미널에 출력하지 않습니다.

```sh
cd "$HOME/moa-projects/moa/deploy"
MOA_BACKUP_DIR="$HOME/moa-before-codef-$(date +%Y%m%d-%H%M%S)"
mkdir -m 700 "$MOA_BACKUP_DIR"
MOA_SQLITE_TMP=$(docker compose -f compose.nas.yml -f compose.mac.yml exec -T app python -c '
import os, sqlite3, tempfile
fd, path = tempfile.mkstemp(prefix="moa-before-codef-", suffix=".sqlite3")
os.close(fd)
source = sqlite3.connect("file:/data/cards.sqlite3?mode=ro", uri=True)
target = sqlite3.connect(path)
source.backup(target)
target.close()
source.close()
print(path)
')
docker compose -f compose.nas.yml -f compose.mac.yml cp "app:$MOA_SQLITE_TMP" "$MOA_BACKUP_DIR/cards.sqlite3"
chmod 600 "$MOA_BACKUP_DIR/cards.sqlite3"
docker compose -f compose.nas.yml -f compose.mac.yml exec -T app python -c 'import pathlib,sys; pathlib.Path(sys.argv[1]).unlink()' "$MOA_SQLITE_TMP"
```

백업 파일과 비밀 키는 채팅·Git에 올리지 않습니다. 백업·복원 시 `codef-storage.key`도 별도로 보존해야 합니다. 키를 잃으면 암호화한 연결 ID를 읽을 수 없습니다.

## 2. 코드와 이미지 업데이트

```sh
cd "$HOME/moa-projects/moa"
# GitHub 접근은 gh 로그인(HTTPS)을 사용합니다. 처음 한 번: gh auth login → gh auth setup-git
git pull --ff-only origin main
cd deploy
docker compose -f compose.nas.yml -f compose.mac.yml --profile codef build app codef-worker
docker compose -f compose.nas.yml -f compose.mac.yml up -d app
```

Gmail은 별도 작업자입니다. CODEF를 켠다고 Gmail을 중지·초기화하거나 메일을 수정하지 않습니다.

## 3. 암호화 키 최초 준비

기존 CODEF 데모 앱 키는 그대로 사용합니다. 연결 ID 저장용 키만 최초 한 번 추가합니다.

```sh
docker compose -f compose.nas.yml -f compose.mac.yml run --rm --no-deps \
  --user 0 -v moa_mac-secrets:/setup-secrets \
  app python scripts/connect-codef-card.py --init-key
```

기존 키가 있으면 검증 후 그대로 유지합니다. `codef-storage.key`는 앱 UID 1000의 600 권한으로 비밀 볼륨에 저장하고 컨테이너에는 읽기 전용으로 제공합니다. 임의로 교체하면 기존 연결을 읽을 수 없습니다. 키를 직접 출력할 필요는 없습니다.

## 4. 본인 카드사 연결

아래 `--user owner`는 **모아 로그인 아이디**입니다. NAS·맥·GitHub 아이디가 아닙니다. 공동관리자는 자신의 모아 아이디를 명시하고 본인 카드만 연결합니다.

먼저 삼성 한 곳부터 등록·조회·저장이 정상인지 확인할 수 있습니다.

```sh
docker compose -f compose.nas.yml -f compose.mac.yml run --rm --no-deps \
  app python scripts/connect-codef-card.py --card samsung --user owner
```

처음에는 홈페이지 로그인 정보와 카드사별 본인 확인 값을 숨겨 입력받습니다. 롯데 SMS 인증이 나오면 받은 번호를 터미널에 입력합니다. 등록 성공 뒤에는 **비밀번호·PIN 없이 연결 ID만으로 조회를 검증**합니다. 처음 수집한 지출도 검증 후 바로 저장합니다.

현대는 승인 상품의 `loginCardNo`와 계정 등록의 `cardNo`가 서로 다른 요청 필드입니다. 입력받은 카드번호를 등록 요청에서는 `cardNo`로 보내고, 직접 승인 조회에서는 기존 `loginCardNo`를 사용합니다. 암호화한 카드 비밀번호는 두 경로 모두 `cardPassword`이며 기본 연결·수동 조회 CLI는 이를 보관하지 않습니다. 아래의 암호화 추가 인증 설정은 별도 선택입니다. `CF-04000` 아래 기관 상세 코드가 `CF-12401`, 누락 키가 `cardNo`라면 코드를 업데이트하고 앱 이미지를 다시 빌드한 뒤 연결합니다. 이 누락을 홈페이지 비밀번호 오류로 해석하지 않습니다.

등록 실패 시 단일 대상 기관의 상세 코드와 허용된 누락 키·고정 주제만 표시합니다. `CF-12800`만으로 비밀번호 오류라고 단정하지 않습니다. 홈페이지의 아이디 로그인과 추가 인증·변경 안내를 먼저 확인하고, 정상인데도 실패하면 코드를 구분해 진단합니다. 여러 기관·부분 성공 응답에서 임의의 오류를 선택하거나 공급자 원문을 출력하지 않습니다.

연결 상태 `ready`는 자동 수집 가능, `needs_auth`는 인증·필수 입력 확인 필요, `needs_review`는 조회 데이터 확인 필요, `error`는 통신·설정 확인 필요, `quota`는 로컬 요청 예산 대기입니다. `verifying`가 계속 남으면 연결 검증 중 취소·중단된 경우일 수 있으므로 같은 명령으로 확인합니다. 기존 연결은 로그인 정보를 다시 받지 않고 연결 ID로 검증합니다. 인증·등록 오류가 난 경우에는 `2`를 선택해 새 아이디·비밀번호로 다시 등록할 수 있습니다. Enter는 종료이며 자동으로 새 비밀번호를 전송하지 않습니다. 한 명령에서 사용자가 선택한 교체는 최대 한 번만 더 진행합니다. 처음부터 새 로그인 정보로 등록하려면 마지막에 `--replace`를 붙입니다.

나머지 카드사는 `samsung`을 `hyundai`, `kb`, `shinhan`, `lotte`, `woori`로 바꿉니다. 6개를 차례로 연결하려면 다음을 사용합니다. 실패한 카드도 자동 반복하지 않고 다음 카드로 넘어가며, 실패한 연결은 수집 대상에서 보류됩니다.

```sh
for MOA_CARD in samsung hyundai kb shinhan lotte woori; do
  docker compose -f compose.nas.yml -f compose.mac.yml run --rm --no-deps \
    app python scripts/connect-codef-card.py --card "$MOA_CARD" --user owner
  MOA_CONNECT_STATUS=$?
  if [ "$MOA_CONNECT_STATUS" -eq 130 ] || [ "$MOA_CONNECT_STATUS" -eq 3 ]; then break; fi
done
```

이미 연결한 카드가 있다면 그 카드는 기존 연결 ID를 다시 확인합니다. `--replace`는 명시적으로 새 등록을 원하는 경우에만 사용합니다. 계정 등록 자체에 대한 CODEF 이용 조건·요청 과금은 운영자 계정의 계약을 확인하세요.

추가 인증을 완료하지 못한 종료 코드 `3`과 사용자 취소 `130`에서는 위 일괄 연결도 중단합니다. 롯데 SMS 처리를 확인할 때는 우선 `--card lotte` 단독 명령으로 실행해 다음 카드 입력과 혼동하지 않도록 합니다.

### 계정 등록 없이 수동 조회·저장하기

롯데의 계정 등록이 `CF-04000` 또는 재개 정보 없는 `CF-04034`로 중단된다면, 계정 등록을 반복하기보다 명세에 있는 **승인내역 직접 로그인 방식**을 별도로 확인할 수 있습니다. `CF-04000`은 일반적인 계정 등록 실패 코드이며 아이디·비밀번호 오류를 입증하지 않습니다. 이 코드만으로 새 비밀번호를 다시 입력받지 않습니다.

2~3단계의 코드·이미지·키 준비를 마친 뒤 맥의 `moa/deploy` 폴더에서 실행합니다.

```sh
docker compose -f compose.nas.yml -f compose.mac.yml run --rm --no-deps \
  app python scripts/connect-codef-card.py --card lotte --user owner --direct
```

`--direct`는 `/v1/account/create`를 거치지 않고 승인내역 상품 API에 직접 로그인해 **최근 7일**을 조회합니다. 필요한 홈페이지 로그인·본인 확인 값을 숨겨 입력하고, CODEF가 재개 가능한 SMS 추가 인증을 요청하면 번호 입력을 기다립니다. 원장 저장에는 기존과 같은 개인 소유권 확인·출처 중복 방지·금액 검증·검토 분리를 적용합니다. 저장된 거래는 ‘사용 내역’ 새로고침으로, 수동 조회 상태는 **계정 → 내 카드 자동 수집 · CODEF**에서 확인합니다.

이 방식은 **실행할 때마다 사용자가 요청하는 수동 조회**입니다. 연결 ID를 만들거나 자동 수집을 활성화하지 않으며, 기존 자동 연결의 상태와 다른 `ready` 카드사의 수집도 바꾸지 않습니다. 로그인 정보·본인 확인 값·인증번호·세션은 처리 중 메모리에서만 사용하고 저장하지 않습니다. 기존 연결 ID가 없어도 사용할 수 있지만 명세서 원장을 정상 검증해 저장하는 것과 향후 무인 인증이 가능한 것은 별개입니다.

`lotte`를 `samsung`, `hyundai`, `kb`, `shinhan`, `woori`로 바꾸면 다른 지원 카드사도 같은 수동 방식을 사용할 수 있습니다. 요청은 아래의 기본 하루 60회 로컬 예산에 포함됩니다. 직접 조회에서도 `CF-04034`와 함께 실제 `continue2Way: true`와 네 연결 정보가 오지 않으면 중단합니다. 문자 도착만으로 세션을 만들거나 과거 인증번호를 재사용하지 않으며, 이 경우에는 CODEF의 해당 상품 추가 인증 규격을 확인해야 합니다. 실제 카드사 성공 여부는 실행 결과로 확인합니다.

## 5. 자동 수집 켜기

등록을 마친 뒤 작업자를 시작합니다.

```sh
docker compose -f compose.nas.yml -f compose.mac.yml --profile codef up -d codef-worker
docker compose -f compose.nas.yml -f compose.mac.yml --profile codef ps
```

한국시간 **00:00·08:00·14:00·20:00**의 가장 최근 회차를 기준으로 수집합니다. 재시작 시 놓친 회차를 모두 몰아서 조회하지 않습니다. 회차별 작업 키와 프로세스 잠금으로 중복 실행을 막습니다. 연결 검증에서 방금 조회한 회차도 중복 호출하지 않습니다.

모아의 **계정 → 내 카드 자동 수집 · CODEF**에서 작업자 응답, 본인 카드사별 상태·마지막 성공 시각·저장 건수·확인 필요 건수를 봅니다. ‘지금 수집 요청’은 본인 수집 가능 연결만 요청하며 2분 간격 제한과 같은 요청 예산을 사용합니다. 작업자가 켜져 있어야 실제 실행됩니다. 이 화면의 연결 상태 새로고침만으로 금융 API를 호출하지 않습니다.

원장에 새 지출이 저장되면 ‘사용 내역’ 또는 대시보드를 새로고침해 확인합니다. 공동관리자의 일반 거래는 본인 화면에 나오지 않습니다. 기존 문자 임시내역은 별도로 유지하며 문자 금액을 원장에 다시 자동 합산하지 않습니다.

### 조회가 실제로 실행되는지 확인하기

1. 본인 계정으로 로그인해 **계정 → 내 카드 자동 수집 · CODEF**를 펼칩니다. 해지한 카드의 연결이 남아 있으면 그 행의 ‘수집 중지’를 누릅니다.
2. **연결 상태 새로고침**을 누르고 확인할 카드의 상태와 **마지막 성공 시각**을 기록합니다. 이 버튼은 저장된 상태를 읽으며 카드사에 새 조회를 보내지는 않습니다.
3. 상태가 **수집 가능**인 카드가 있으면 **지금 수집 요청**을 한 번 누릅니다. 작업자가 요청을 처리하므로 브라우저는 열어 두지 않아도 됩니다. 카드사 응답에 수 분이 걸릴 수 있습니다.
4. 잠시 뒤 **연결 상태 새로고침**으로 마지막 성공 시각이 요청 이후로 바뀌었는지 봅니다. 시각이 갱신되면 해당 카드의 조회·결과 검증을 완료한 것입니다. 새 결제가 없으면 저장 건수가 늘지 않아도 정상입니다.
5. **사용 내역**을 새로고침해 최근 실제 결제와 대조하고, **확인 필요** 건수가 있으면 같은 CODEF 패널의 검토 목록도 확인합니다. 조회 성공과 모든 거래의 자동 저장은 별개이며, 중복·모호한 취소는 검토에 남습니다.

**수동 조회·저장** 행의 마지막 시각은 `--direct`를 실행한 기록입니다. 그 행만 있는 카드는 ‘지금 수집 요청’의 예약 연결 대상이 아니며, 다시 직접 조회해야 시각이 바뀝니다. 카드 행 자체가 없으면 해당 모아 계정에 아직 연결·수동 조회 기록이 없는 상태입니다.

**연결·인증 확인 필요**나 **조회 내역 확인 필요** 상태의 카드는 자동으로 다시 조회하지 않습니다. 먼저 그 행의 안내를 확인합니다. **로컬 요청 예산 대기**는 당일 예산을 사용한 상태입니다. **수집 작업자 응답 없음**이 계속 보이면 맥의 `moa/deploy` 폴더에서 다음으로 컨테이너 상태를 봅니다.

```sh
docker compose -f compose.nas.yml -f compose.mac.yml --profile codef ps
docker compose -f compose.nas.yml -f compose.mac.yml logs --tail 50 codef-worker
```

위 두 명령은 상태와 로그를 읽으며 새 카드사 조회를 요청하지 않습니다. 작업자가 실행 중이어도 계정 등록·상품 권한·추가 인증을 완료했다는 뜻은 아니므로 카드별 마지막 성공 시각까지 확인해야 합니다.

## 중복·취소·불확실한 내역 처리

- 승인 날짜·시각·승인번호·카드 식별자를 HMAC으로 묶어 재조회 중복을 방지합니다. 전체 카드번호·승인번호 원문은 저장하지 않습니다.
- 같은 카드·날짜·가맹점·금액의 기존 명세서가 있으면 자동 추가하지 않고 중복 후보로 남깁니다. 같은 가격의 실제 별도 결제라면 본인이 ‘별도 거래로 저장’을 선택할 수 있습니다.
- 일치하는 CODEF 원승인이 있는 전체취소는 해당 원장 금액을 0으로, 취소금액이 명확한 부분취소는 순금액으로 갱신합니다. 기존 분류·주석은 유지합니다. 원승인을 못 찾거나 취소금액이 불명확하면 임의로 음수 거래를 추가하지 않습니다.
- 삼성 등의 응답에서 같은 카드·승인번호·날짜·시각·가맹점에 이용금액이나 승인·취소·거절 상태가 다르게 오면, 어느 금액·상태가 최종인지 추측하지 않고 **금액 미확정 검토 묶음**으로 남깁니다. API의 ‘이용금액’을 항상 같은 원금으로 가정하지 않습니다. 그 묶음은 합산·최댓값·마지막 행으로 계산하지 않으며, 함께 반환된 다른 정상 승인 내역은 검증 후 저장할 수 있습니다. 같은 식별자에서 가맹점까지 다르거나 필수 형식이 잘못된 목록은 해당 조회 전체를 저장하지 않습니다.
- 이용금액이 달라 확정할 수 없는 묶음과 승인·거절이 함께 온 묶음은 이후 조회에 한 가지 상태만 나와도 자동 저장을 재개하지 않습니다. 기존 지출 금액을 유지하며 ‘금액 확인 필요’로 표시합니다. 명세서와 대조하고, ‘검토에서 제외’는 확인 목록만 정리하며 기존 원장을 변경하지 않습니다.
- 부호·통화가 불명확하거나 외화인 행은 확인 필요로 남깁니다. 식별자·날짜·금액 등 필수 형식이 잘못된 응답은 해당 조회 전체를 저장하지 않고 연결 확인 상태로 중단합니다.
- 직접 삭제한 자동 수집 묶음은 재조회로 몰래 복원하지 않습니다. 검토에서 제외해도 기존 원장은 수정하지 않습니다.
- **CODEF 저장 뒤 명세서를 나중에 업로드하면** 기존 ‘지출 관리 → 중복 검토’에서 출처 간 중복을 확인해야 합니다. 서로 다른 출처를 확정 근거 없이 자동 병합하지 않습니다.
- 예약 수집은 최근 30일, `--direct` 수동 조회는 최근 7일을 대상으로 합니다. 조회 범위보다 오래된 원승인의 늦은 취소나 장기간 중단 중 누락은 명세서로 대조해야 합니다. 과거 전체 내역·청구액·납부 상태를 자동 확정하는 기능은 아닙니다.

## 요청 예산·인증 대기·중지

로컬 요청 예산 기본값은 한국 날짜 하루 **60회**입니다. 자동 연결 도구·작업자와 `--direct` 수동 저장의 OAuth 발급, 계정 등록, 조회와 추가 인증 각각을 호출 전에 예약하고 실패 요청도 차감합니다. 작업자 토큰은 메모리에서 1시간 이내 재사용하며 디스크에 저장하지 않습니다. 예산 설정은 `.env`의 `MOA_CODEF_DAILY_REQUEST_LIMIT`로 조절하고, 실제 계약 한도·과금 조건을 확인한 뒤 정합니다.

이 제한은 CODEF의 무료 제공량을 뜻하지 않으며 공급자 한도 초기화 시각을 보증하지 않습니다. 기존 `verify-codef-card.py` 일회성 시험과 개발자 인증 버튼은 이 장부 밖의 별도 호출이므로 무제한 시험을 병행하지 마세요. 두 사람이 각각 카드사 6곳을 하루 4회 수집하면 정기 조회만 48회이며 OAuth·계정 등록·추가 인증·수동 조회가 더해집니다. 필요 시 계약 범위에서 예산을 조절하거나 연결 수를 줄입니다.

추가 인증·PIN·누락 파라미터·잘못된 응답 등으로 중단된 카드는 다음 예약 때 로그인 실패를 반복하지 않습니다. 해당 카드의 연결 명령을 다시 실행해 확인합니다. 앱 키·저장 키가 처리 중 바뀌었거나 계정이 비활성화되면 이전 연결의 늦은 결과를 저장하지 않습니다. 키 변경으로 중단한 결과를 성공으로 표시하거나 마지막 성공 시각을 갱신하지 않습니다. 연결을 교체·중지한 동안 처리 중이던 결과도 버전 검사로 폐기합니다.

본인 카드의 ‘수집 중지’ 버튼은 그 연결만 중지합니다. 전체 작업자를 중지하려면 다음을 실행합니다. 볼륨은 삭제하지 않습니다.

```sh
docker compose -f compose.nas.yml -f compose.mac.yml --profile codef stop codef-worker
```

## NAS에서 사용하는 경우

기본 `compose.nas.yml`만 사용합니다. 키 준비 명령은 `-v "$PWD/secrets:/setup-secrets"`를 쓰고, 나머지는 Mac 추가 파일을 빼면 됩니다. 같은 연결·DB 복사본을 NAS와 맥에서 동시에 수집하지 않습니다. 실제 Mac·CODEF 계정 등록·연결 ID 조회·재인증 주기는 운영 환경에서 최종 확인해야 합니다.


## 로그인 정보 재입력과 조회 데이터 오류 구분

‘같은 승인 식별자의 응답이 서로 다릅니다’는 아이디·비밀번호 오류가 아닙니다. 처리 버전 3은 같은 가맹점의 금액·상태 충돌을 해당 묶음의 검토로 분리하며, 다른 정상 거래는 저장합니다. 가맹점 같은 출처 정보까지 충돌하면 해당 조회 전체를 `needs_review`로 보류합니다. 어느 경우도 새 로그인 정보를 요구하지 않습니다. 구버전에서 이 오류를 `needs_auth`로 표시한 연결도 업데이트 시 상태만 교정합니다. 연결 ID·원장·기존 비밀번호 설정은 건드리지 않습니다.

구버전 삼성 오류가 남아 있다면 2단계의 코드·이미지 업데이트 후 `--card samsung --user owner`로 기존 연결을 재검증합니다. 터미널에 **승인 내역 처리 버전: 3**이 표시되는지 확인합니다. 기존 `needs_review` 상태는 코드 업데이트만으로 금융 API를 다시 호출하지 않으므로 명시적인 재검증이 필요합니다. 같은 오류를 이유로 `--replace`를 반복하지 않습니다.

인증·기관 등록에 실패한 경우에는 CLI에서 `2`를 선택하면 새 정보를 숨겨 입력받습니다. 등록 성공 확인 전에 기존 로컬 연결을 덮어쓰지 않습니다. 새 연결의 조회 인증까지 실패하거나 SMS 입력 중 취소하면 기존 연결이 있을 때 그 연결을 복원합니다. 다만 동시에 다른 작업에서 연결을 교체·중지했다면 버전 검사로 이를 덮어쓰지 않습니다. 원문 비밀번호나 오류 전문은 저장하지 않습니다.

`CF-04000` 일반 계정 등록 실패, `CF-12834` 잠금이나 `CF-03002/CF-04034` 추가 인증은 코드만으로 잘못된 비밀번호라고 단정하지 않습니다. 이 코드만으로 새 비밀번호 재입력을 유도하지 않으며 인증번호 입력을 시작한 뒤의 오류도 새 비밀번호 교체로 돌리지 않습니다. 특히 롯데에서 문자가 왔더라도 CODEF 응답에 재개 플래그와 연결 정보가 없으면 빈 세션을 만들어 전송하지 않습니다. 사용자가 이미 종료한 명령에서 받은 예전 인증번호를 새 요청에 재사용하지 않습니다.

롯데의 계정 등록 `errorList`에 단일 기관 추가 인증이 담겼거나 연결 정보가 `twoWayInfo` 안에 있어도, 기관이 맞고 `continue2Way`가 실제 True이며 네 연결 필드가 모두 있을 때에만 번호 입력으로 이어갑니다. 확인된 `CF-04034` 로그도 이 조건이 충족된 경우만 처리하고 코드만 보고 인증 방식을 추측하지 않습니다. 재개 정보가 부족하면 누락된 키와 플래그 안내만 표시하며 이름·번호·토큰·세션 값은 출력하지 않습니다. 이 경우에는 CODEF 계정 등록 단계의 추가 인증 지원 조건을 확인해야 하며, 새 아이디를 넣는 것만으로 해결됐다고 보지 않습니다.

인증번호 입력 중 빈 값이나 형식이 다른 값으로 Enter를 눌러도 입력을 종료하지 않고 로컬에서 다시 기다립니다. 이 동안 CODEF 요청은 추가하지 않습니다. 올바른 형식의 번호를 입력해야 다음 요청을 보내고, Ctrl+C로 즉시 취소할 수 있습니다. 실제 SMS 유효기간은 카드사 정책을 따릅니다.


### 현대 등록 성공 뒤 cardNo 누락이 나오는 경우

등록 성공 뒤 연결 ID 조회에서 `CF-12401`과 `cardNo`가 나오면 계정 등록 성공과 무인 조회 성공을 구분합니다. 같은 아이디·비밀번호로 재등록하지 않습니다. 현대 직접 승인 요청에는 입력한 번호를 `loginCardNo`와 `cardNo`에 함께 보내지만 `inquiryType=1` 전체 조회는 유지합니다. 카드번호·PIN을 영속 보관하지 않으므로, 연결 ID만으로 소지 확인을 완료하지 못한 카드는 자동 수집 가능으로 표시하지 않습니다. 수동 조회·저장 또는 공급자가 지원하는 다른 인증 방식을 별도로 확인해야 합니다. 공식 규격은 [개인 승인내역 API](https://developer.codef.io/products/card/common/p/approval)를 참고합니다.


## 현대 암호화 추가 인증으로 자동 수집하기

현대 연결 ID 등록은 성공해도 승인 조회가 매번 `cardNo`와 `cardPassword`를 요구할 수 있습니다. 카드번호만 넣었을 때 `cardPassword` 누락이 확인됐다면, **명시적으로 보관에 동의한 운영자**는 이 기능을 선택할 수 있습니다. 일반 연결 명령이나 화면 새로고침만으로 이 보관을 시작하지 않습니다. [공식 승인 조회](https://developer.codef.io/products/card/common/p/approval)의 RSA 암호화 형식을 사용하며 같은 암호문 재사용이 가능한지는 실제 계정에서 두 요청으로 검증합니다.

먼저 코드와 이미지를 2단계대로 업데이트합니다. Mac에서 다음을 실행합니다.

```sh
cd "$HOME/moa-projects/moa/deploy"
docker compose -f compose.nas.yml -f compose.mac.yml run --rm --no-deps \
  -v moa_mac-secrets:/setup-secrets \
  app python scripts/configure-codef-card-auth.py --user owner
```

홈페이지 아이디·비밀번호는 다시 받지 않습니다. 전체 카드번호와 카드 비밀번호 4자리만 TTY에서 숨겨 입력합니다. PIN은 메모리에서 CODEF 공개키로 RSA 암호화하고, 그 **동일한 암호문**으로 오늘 하루의 조회를 두 번 확인합니다. 첫 오류·추가 인증·응답 형식 오류에서 중단하며 파일을 저장하지 않습니다. 두 요청이 성공한 경우에만 카드번호와 RSA 암호문을 기존 저장 키의 Fernet으로 감싸 `/setup-secrets/codef-card-auth/`에 보관합니다. 이 폴더는 기존 `moa_mac-secrets` 볼륨의 하위 폴더이고 앱·작업자는 같은 파일을 `/run/moa-secrets/codef-card-auth/`에서 읽기 전용으로 읽습니다.

- 비밀 폴더는 700, 파일은 600이며 PIN 평문·카드번호 원문·RSA 암호문을 로그·Git·DB·브라우저에 넣지 않습니다. RSA 암호문도 재사용 가능한 인증정보이므로 비밀 백업 범위에 포함됩니다.
- DB의 `codef_links.card_auth_ref`에는 무작위 파일 참조만 추가합니다. 기존 테이블을 재생성하거나 원장·연결 ID·다른 카드 설정을 초기화하지 않습니다.
- 파일은 사용자·현대카드·현재 연결 ID의 HMAC·앱 설정 해시에 결합합니다. 다른 사람의 파일, 다른 연결, 앱 키 변경, 저장 키 변경, 조회 도중 파일 변경은 성공 결과로 반영하지 않습니다.
- 새 파일을 만든 뒤 DB 잠금 안에서 계정·연결 버전을 다시 확인해 참조를 확정합니다. 실패한 새 파일은 정리하고, 교체된 이전 파일은 더 이상 참조하지 않은 뒤 정리합니다.
- 설정 직후 **보관한 파일을 새로 읽어 최근 30일 조회·저장**까지 확인합니다. 여기까지 성공해야 `ready`가 되고 이미 완료한 현재 회차는 다시 조회하지 않습니다. 작업자는 기존 한국시간 하루 4회 일정과 요청 예산을 유지합니다.
- 인증·권한 오류는 자동 반복하지 않습니다. 키가 바뀌면 이전 PIN 암호문을 임의 변환하지 않고 입력부터 다시 검증합니다. 금액이 불확실한 내역은 기존 처리 버전 3의 검토 분리를 유지합니다.

추가 인증 보관을 해제하려면 같은 쓰기 마운트에서 실행합니다. 연결 ID·기존 원장·다른 카드사는 보존하고 현대는 인증 확인 대기로 바뀝니다.

```sh
docker compose -f compose.nas.yml -f compose.mac.yml run --rm --no-deps \
  -v moa_mac-secrets:/setup-secrets \
  app python scripts/configure-codef-card-auth.py --user owner --disable
```

NAS에서는 Mac 추가 파일을 빼고 `-v "$PWD/secrets:/setup-secrets"`를 사용합니다. 기존 비밀 볼륨과 `codef-storage.key`를 함께 백업하며, 해제·재설정 작업도 본인 모아 아이디로 실행합니다. 공동인증서 방식 전환은 이 기능과 별도의 인증 경로입니다.
